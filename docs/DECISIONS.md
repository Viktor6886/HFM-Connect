# Журнал архитектурных и технических решений

Формат: ID · дата · решение · обоснование · последствия. Отменённые решения не удаляются,
а помечаются «заменено D-xxx».

## D-001 · 2026-11-08 · Нативный UART ESP32-S3 + внешний K-Line трансивер вместо USB-Host → FTDI
**Обоснование.** Задание требует «ESP32-S3 с внешним K-Line-трансивером». REV 1.4 §6
описывал цепочку ESP32 USB Host → FT232RL → KKL; она добавляет USB-стек, драйвер FTDI и
не даёт точного управления BREAK/паритетом. Прямой UART даёт BREAK через инверсию TXD,
побайтное переключение паритета и измеримые тайминги.
**Последствия.** FTDI/KKL-кабели не используются; путь USB Host — в ROADMAP как опция.

## D-002 · 2026-11-08 · Без внешних библиотек Arduino
WebServer, WiFi, DNSServer, ESPmDNS, LittleFS, Preferences — из ядра esp32; JSON —
собственный `JsonWriter`. Сборка в Arduino IDE «открыл .ino → загрузил» без менеджера
библиотек; меньше рисков несовместимости версий. Цена: синхронный WebServer, опрос
вместо WebSocket (достаточно для 3 Гц обновления Live Data).

## D-003 · 2026-11-08 · Эмуляция SPACE-паритета через EVEN/ODD побайтно
UART ESP32 не поддерживает SPACE. Для байта с чётным числом единиц — EVEN, с нечётным —
ODD: бит паритета = 0. После TX префикса (8N1) приёмник переключается в EVEN, чтобы
принимать и 10-, и 11-битные кадры ЭБУ; ошибки паритета/кадра считаются, но не
отбрасывают байты. Требует проверки осциллографом (H2).

## D-004 · 2026-11-08 · Платформонезависимое ядро + host-тесты
Протокол, декодеры, профили, сервисы и guard не зависят от Arduino и компилируются на ПК
(`g++`/`zig c++`). Позволяет тестировать без ЭБУ и в CI.

## D-005 · 2026-11-08 · Белый список префиксов в транзакционном слое
Неизвестные коды не отправляются никогда (REV 1.1: перебор 00–FF опасен). Префиксы записи
требуют одноразового токена; проверка в `HfmSession`, а не в UI.

## D-006 · 2026-11-08 · Keep-alive = чтение F0:00 вместо «10 00»
REV 1.1 описывает keep-alive `10 00` каждые 1300 мс простоя, но `10` входит в
последовательность стирания DTC. Безопасная альтернатива — чтение байта идентификации. Отключаемо.
Необходимость keep-alive (сторожевой таймаут ЭБУ) не доказана.

## D-007 · 2026-11-08 · Нейтральные метки банков DTC (C-01)
Источники REV 1.1 трактуют банки F1 противоположно. Метки «текущие/сохранённые»
показываются только если профиль ЭБУ утверждает отображение. Иначе — «Банк A/B».
Заменено D-018.

## D-008 · 2026-11-08 · Запись только для эталонного ЭБУ, в «Режиме инженера», с ключом WRITE-EN
REV 1.4 требует блокировки до аппаратной верификации; спецификация REV 1.1 описывает
запись только для эталонного ЭБУ 013 545 13 32 / 41-00. Прошивка повторяет эту границу и добавляет: режим инженера,
аппаратный ключ, свежие предусловия, фразу, токен 20 с, FAULT_STOP. Для остальных ЭБУ —
БЛОК независимо от настроек.

## D-009 · 2026-11-08 · 9-значное кодирование и обучение дросселя — без команд
Команды заводского тестера не восстановлены ни в одном источнике; генерация кода по чекбоксам запрещена
(REV 1.4 §14). Реализованы: чтение байта кодировки (РЕК), ручной ввод кода для архива,
визуальная проверка CTP/WOT/угла. Запись — БЛОК.

## D-010 · 2026-11-08 · DM/OBD-II не реализуется
N59/1 — отдельный блок, отдельная линия и пространство P-кодов. Задание исключает OBD-II.
Разъём X11/22 описан только как предупреждение.

## D-011 · 2026-11-08 · WebUI встроен в прошивку (gzip PROGMEM)
Не требует загрузки LittleFS-образа из Arduino IDE. LittleFS используется только для данных
(записи, отчёты) и форматируется автоматически.

## D-012 · 2026-11-08 · Нормы применяются только при выполненных условиях
Красная подсветка — только при валидном чтении, известной формуле и выполненных условиях
(ОЖ > 80 °C, обороты ХХ 450–1000). Иначе NOT_APPLICABLE (REV 1.4 §10.2, D-012).

## D-013 · 2026-11-08 · Даты в базе автомобилей — только из источников
Где источник не указывает дату (W210, часть W124/W202) — поле пустое. Записи шасси,
известные лишь по общим сведениям, помечены ГИП.

## D-014 · 2026-11-08 · Импульсный режим через тот же трансивер
Удержание линии в 0 инверсией TXD 2–4 с, измерение импульсов по уровню RX. Выключен по
умолчанию; стирание импульсами не реализовано. Рекомендована отдельная перемычка (M14-15).

## D-015 · 2026-11-08 · Заводские PDF не публикуются в публичном репозитории
Авторские права Mercedes-Benz/третьих лиц. В репозитории — собственные спецификации проекта
(`docs/specs/`), извлечённые таблицы (`data/`) и реестр источников (SOURCES.md).

## D-016 · 2026-11-08 · Режим симулятора удалён из прошивки
Владелец собрал адаптер; прошивка работает только с реальной K-Line. `SimEcu` перенесён в
`tests/host/` и используется только host-тестами; mock-сервер WebUI удалён. Замещает
соответствующую часть D-011 (симулятор в WebUI).

## D-017 · 2026-11-08 · Нейтральные ссылки на источники
В текстах репозитория основой протокола указывается спецификация REV 1.1–1.4 и заводская
документация; сторонние программы как основа ПО не упоминаются. Файлы спецификаций и
исходные материалы анализа хранятся локально и в репозиторий не входят (вместе с D-015).

## D-018 · 2026-11-08 · Назначение банков DTC по правилу OEM
Engine 104/111 Diagnostic Manual 11/3: перемежающиеся неисправности бывают только в
сохранённых. При каждом чтении F1 прошивка ищет такие коды; если они только в одном банке,
он считается сохранённым (ЗАВ-правило). Без такой улики используется профиль: для Bosch HFM
по умолчанию A = сохранённые (ГИП). Замещает D-007.

## D-019 · 2026-11-08 · Тайминги K-Line настраиваются в WebUI
BREAK, пауза после BREAK и тайм-аут «эхо + ответ» хранятся в NVS (по умолчанию 177/214/750 мс)
и применяются без перепрошивки. Синхронизация ищет пару AA 55 среди первых 4 байт
(допускает посторонний байт после фронта BREAK). UART-драйвер не удаляется при отключении:
TX остаётся в «1», вход трансивера не плавает.

## D-020 · 2026-11-08 · Импульсные коды расшифровываются по заводской таблице N→A
Таблицы Engine 104/111 (11/8–11/15) перенесены в `ImpulseDecoder.cpp`; группа кодов для N
выбирается по двигателю выбранного автомобиля (M104/M111). Для M111 тексты кодов с иной
нумерацией цилиндров/катушек берутся из заводской таблицы (`dtc::m111Text`).

## D-021 · 2026-11-09 · Транспорт: USB K-Line адаптер FTDI через USB-хост ESP32-S3
Владелец использует готовый K-Line адаптер на FTDI. Драйвер `FtdiLink` (ESP-IDF `usb_host`
из ядра Arduino, без внешних библиотек): SIO-запросы FTDI (reset, baud 9600, flow off,
latency 1 мс, DTR/RTS, SET_DATA с паритетом SPACE и битом BREAK), 2 байта статуса в каждом
пакете IN (счётчики паритета/кадра/BREAK/переполнения). Горячее подключение адаптера.
Автоподключение после загрузки с удвоением паузы 2→15 с; «Отключить» приостанавливает его.
Keep-alive F0:00 — 700 мс. UART-трансивер остаётся вариантом сборки (`HFM_TRANSPORT_FTDI 0`).

## D-022 · 2026-11-09 · DTC: заводские карты вариантов, ремапы по позиции
Ремапы REV 1.1 §14 ключуются позицией бита (подтверждено заводскими картами: 6 цил. Bosch
≥ 'I' — позиции 35/39/41 → 045/047/039). Карта выбирается по цилиндрам (из выбранного
автомобиля), производителю и F0:26; без числа цилиндров — базовая таблица + позиционные
ремапы. Неиспользуемая позиция карты — RAW, без догадки.

## D-023 · 2026-11-09 · Вариант VDO и формулы Live Data
ЭБУ не Bosch в диапазоне HFM — кандидат VDO: опрос по адресам шаблонов заводского тестера
(префиксы 12/22/23 — экспериментальное чтение), маски `bit_v0_old`. Основная формула O2 —
формула заводского тестера (знаковая, согласуется с нормой −200…+1000 мВ), 4·raw —
альтернатива. Заданные обороты ХХ: 21:D7 при F0:26 < 0x41, иначе 20:67.

## D-024 · 2026-11-09 · Собственный драйвер FTDI вместо компонента `usb_host_ftdi_vcp`
Компонент Espressif `usb_host_ftdi_vcp` (менеджер компонентов ESP-IDF, C++, зависит от
`usb_host_cdc_acm`/`usb_host_vcp`) не является библиотекой Arduino и не подключается в
Arduino IDE без переноса исходников (D-002). Он работает поверх той же USB Host Library
ESP-IDF и выдаёт те же vendor-запросы FTDI SIO, что и `FtdiLink` (RESET, BAUDRATE,
SET_DATA, MODEM_CTRL, LATENCY). Обнаружение адаптера (перечисление USB-устройства, в том
числе за внешним хабом) выполняется USB Host Library до любого драйвера класса — замена
драйвера его не меняет. Для поиска причин добавлена диагностика `/api/usb`: список
устройств (хаб, порт хаба, скорость) и журнал ошибок USB-стека ESP-IDF.

## D-025 · 2026-11-10 · Восстановление USB

Клиент регистрируется до активации корневого порта. События ускоряют поиск, а периодический обход готовых адресов покрывает пропущенные события. Ошибка перечисления запускает независимый таймер повторов. Потеря синхронизации с ЭБУ при исправном FTDI обрабатывается в DiagEngine и не запускает сброс USB.

## D-026 · 2026-11-10 · Подключение к KKL-адаптеру как у работающего ПК-тестера
Адаптер владельца (FT232RL KKL, три провода к ЭБУ) работает с ПК-тестером, а с ESP32-S3 ЭБУ
не отвечал: эхо AA было, 55 — нет. Сверка с кодом ПК-тестера (PROTOCOL §2.1) показала, что
прошивка включала DTR и RTS, а обе ПК-программы держат их выключенными, и отличалась
последовательность пробуждения. Решение: транспорт FTDI повторяет ПК-тестер — DTR/RTS
сняты, после BREAK заново 9600 + SPACE, AA в фиксированный момент от начала BREAK, при
молчании 00/00/AA без нового BREAK. Алгоритм вынесен в платформонезависимый `KLineWake`
с host-тестами. Если ЭБУ молчит, `kwake::Planner` перебирает BREAK 165/160/130 мс (значения
ПК-тестера) и режимы DTR/RTS; найденный профиль сохраняется до сбоев. По каждой попытке
публикуется диагностика линии (BREAK принят адаптером, эхо, ответ ЭБУ, принятые байты).
Корневой USB-порт включается через 1,5 с после старта (хаб и адаптер успевают включиться).

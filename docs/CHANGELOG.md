# История изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии прошивки — `HFM_FW_VERSION`.

## [0.3.2] — 2026-11-09

### Добавлено
- Электрическая диагностика USB-порта: маршрут внутреннего PHY на OTG (RTC_CNTL_USB_CONF,
  USB_WRAP), состояние корневого порта (HPRT: питание, подключение, уровни D+/D−) — на
  странице *Подключение* и в `/api/status` (`phy_otg`, `port_connected`, `dp`, `dm`).
  «D+/D− без сигнала» однозначно означает, что FTDI-чип не подтянул D+: нет 5 В VBUS на
  адаптере или он не в разъёме USB (OTG).

### Исправлено
- Причина «не обнаружен» обрезалась («…или ад»): буферы причины 160 Б, сообщений 256 Б,
  тексты сокращены.
- Страница *Подключение* называла транспорт «Адаптер K-Line на UART».

## [0.3.1] — 2026-11-09

### Исправлено
- FTDI-адаптер, уже подключённый при включении, мог не определиться никогда: событие
  USB «новое устройство» приходило до регистрации клиента. Теперь уже определённые
  USB-устройства опрашиваются явно (раз в 1 с, пока адаптера нет).
- Сообщения длиннее 96 байт обрезались посреди русской буквы («…кабель и пит?»): буферы
  сообщений увеличены до 192 байт, JSON отбрасывает неполные UTF-8 последовательности.

### Добавлено
- Диагностика USB: причина «адаптер не обнаружен» (нет USB-устройств — нет 5 В VBUS или
  не тот разъём; найдено устройство не FTDI с его VID:PID; ошибка захвата интерфейса;
  ошибка запуска USB-хоста), число устройств на разъёме, последнее VID:PID — на странице
  *Подключение*, в `/api/status` (`adapter.note`, `usb_devices`, `dev_events`,
  `seen_vid_pid`) и в журнале Serial (`[usb] …`, 115200 Бод, разъём UART/COM).

## [0.3.0] — 2026-11-09

### Добавлено
- Транспорт USB K-Line адаптер FTDI на разъёме USB-OTG ESP32-S3 (USB-хост, горячее
  подключение), состояние адаптера в WebUI (D-021).
- Автоподключение к ЭБУ после загрузки и при подключении адаптера, повтор 2–15 с;
  переключатель в настройках; keep-alive F0:00 каждые 0,7 с.
- Заводские карты DTC для 7 вариантов (4/6 цил., Bosch/VDO, F0:26), карта показывается на
  странице DTC (D-022).
- Профиль «кандидат VDO» и план опроса Live Data по адресам VDO (эксп., D-023).

### Исправлено
- Ремапы DTC применялись к коду вместо позиции бита.
- Основная формула O2 — формула заводского тестера (4·raw давала 0…1020 мВ без
  отрицательной области нормы).
- Заданные обороты ХХ: источник 21:D7 для ЭБУ с F0:26 < 0x41; 0 при остановленном двигателе.
- Подпись бита q5 — «Впускной коллектор (частичная нагрузка)».

## [0.2.0] — 2026-11-08

### Изменено
- Режим симулятора удалён из прошивки и WebUI: только реальная K-Line (D-016). Модель ЭБУ
  осталась в `tests/host/` для автоматических тестов; mock-сервер удалён.
- UART-драйвер K-Line устанавливается при старте и не удаляется: TX удерживается в «1».
- Синхронизация ищет `AA 55` среди первых 4 байт после BREAK.
- Тексты репозитория: ссылки на спецификацию REV 1.1–1.4 и заводские документы (D-017);
  данные перенесены в `data/protocol/` (без служебных ссылок), спецификации не публикуются.

### Добавлено
- Тайминги K-Line (BREAK / пауза / тайм-аут) настраиваются в WebUI и хранятся в NVS (D-019).
- Чтение F0:26/27 (страница ПЗУ, адрес дескрипторов Live Data).
- Автоопределение банков DTC по заводскому правилу «перемежающиеся — только сохранённые» (D-018).
- Заводские таблицы импульсных кодов N → трёхзначный код для M104 и M111 (D-020).
- Тексты кодов M111 (4 цилиндра, пары катушек 1/4 и 2/3).
- Пометка возможных замещающих значений ОЖ/IAT/HFM в Live Data при DTC датчика.
- Справочник проверок датчиков ОЖ B11/3 и IAT B17 (напряжение/сопротивление, OEM).
- Подсказка о смысле текущих неисправностей только при работающем двигателе.

## [0.1.0] — 2026-11-08

### Добавлено
- Платформонезависимое ядро: `HfmSession` (транзакции префикс/селектор/аргумент, эхо/ACK,
  дедлайн 750 мс, 3 попытки синхронизации, белый список префиксов, токен записи),
  `TraceLog` (RAW TX/RX, JSON/JSONL), `HfmDecode` (формулы REV 1.1, таблицы температур),
  `HfmIdent` (F0 28 байт), `HfmDtc` (152 позиции, последовательные ремапы, каталог 163 кодов),
  `HfmProfiles` (16 записей автомобилей, 6 профилей разъёмов, профили ЭБУ, capability, нормы I07),
  `HfmLive` (full8, расширенные рецепты, 3 слоя оценки), `HfmServices` (адаптации, кодировка,
  VIN, карантинные рецепты стирания/сброса/продувки), `ServiceGuard`, `ImpulseDecoder`.
- Arduino-слой: `KLineUart` (ESP-IDF UART, BREAK через инверсию, эмуляция SPACE), `DiagEngine`
  (задача FreeRTOS, задания, опрос, keep-alive, watchdog теста, запись CSV), `WebApi` (REST),
  `NetManager` (AP+STA, captive DNS, mDNS), `Settings` (NVS), `HFMConnect.ino`.
- WebUI (iOS-стиль, 11 разделов, светлая/тёмная тема, графики canvas) встроен gzip.
- Host-тесты (39), трасса replay, сверка таблиц, GitHub Actions CI.
- Документация: README, CLAUDE.md, ARCHITECTURE, PROTOCOL, ECU_COMPATIBILITY,
  DIAGNOSTIC_FUNCTIONS, HARDWARE, BUILD, TESTING, DECISIONS, ROADMAP, PROGRESS,
  SESSION_HANDOFF, SOURCES; спецификации REV 1.1/1.3/1.4 в `docs/specs/`.

### Известные ограничения
- Ничего не проверено на реальном ЭБУ; тайминги и уровни трансивера не измерены.

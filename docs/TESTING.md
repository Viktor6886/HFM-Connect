# Методика испытаний

Испытания делятся на **программные** (без ЭБУ) и **аппаратные** (автомобиль/стенд).
Программные испытания подтверждают внутреннюю согласованность с реконструированным
протоколом, но **не** поведение реального ЭБУ. Не смешивать результаты.

## 1. Программные испытания (автоматические)

| Набор | Команда | Что проверяет |
|---|---|---|
| Host-тесты C++ | `python tools/run_host_tests.py` | декодеры (векторы HFMreader), ID, DTC/ремапы/каталог, профили и capability, сеанс на SimEcu (BREAK/SYNC/эхо/ACK/тайм-аут), политика команд, Live Data и нормы, адаптации/кодировка, ServiceGuard, карантинные рецепты, журнал JSONL, импульсный декодер, replay трассы |
| Сверка таблиц | `python tools/check_tables.py` | LUT 256×2, маски, базовые коды, ремапы, каталог DTC = данные анализа |
| WebUI | `python tools/build_webui.py --check`, `node --check webui/app.js` | бандл актуален, синтаксис JS |
| Прошивка | `arduino-cli compile … firmware/HFMConnect` | компиляция для ESP32-S3 |
| CI | `.github/workflows/ci.yml` | всё перечисленное при каждом push/PR |

### Трассы

- `tests/traces/sim_*.jsonl` — **синтетические** трассы, записанные с SimEcu (transport
  `sim`). Пересоздание: `HFM_REGEN_TRACES=1 python tools/run_host_tests.py golden`.
- `tests/traces/ecu_*.jsonl` — место для трасс реальных ЭБУ (пока нет). Каждая трасса
  проигрывается тем же `ReplayLink`; формат — `/api/trace.jsonl`.

### Сценарии отказов (покрыты тестами)

нет синхронизации (3 попытки) · несовпадение эха · неверный ACK · тайм-аут с частичным
приёмом · неизвестный префикс · запись без токена · селектор без контекста · неполный цикл
(MAF-пара отбрасывается) · просроченный/повторный токен · неверная фраза · смена ЭБУ между
prepare и execute · разомкнутый WRITE-EN · неизвестное напряжение · устаревшие обороты ·
FAULT_STOP до квитирования · расхождение запроса с трассой.

## 2. Ручные испытания WebUI

`python tools/dev_server.py` (mock API) или симулятор на устройстве: все 11 разделов,
светлая/тёмная тема, ширина 375 px / 768 px / ≥ 900 px, отсутствие ошибок в консоли.

## 3. Аппаратные испытания (требуются, не выполнены)

| № | Испытание | Критерий | Статус |
|---|---|---|---|
| H1 | Питание и уровни трансивера без ЭБУ | K ≈ 12 В в покое, нет 5 В на GPIO | не выполнено |
| H2 | Осциллограмма BREAK/AA | 177 ± 5 мс, байт AA 9600 Бод, бит паритета 0 | не выполнено |
| H3 | Синхронизация с ЭБУ (3 холодных старта, 3 повторных) | AA 55 каждый раз | не выполнено |
| H4 | F0 00–1B | 28 байт, повторяемо, сверка с этикеткой ЭБУ | не выполнено |
| H5 | F1 00–1F с созданной неисправностью (разъём датчика) | бит появляется/исчезает; определить банки (C-01) | не выполнено |
| H6 | Live Data full8 vs HHT/другой прибор | обороты, ОЖ, MAF в пределах погрешности | не выполнено |
| H7 | Адаптации/кодировка vs HHT | совпадение значений | не выполнено |
| H8 | Обрыв K-Line / снятие зажигания во время опроса | Error, без повторов записи, восстановление чтения | не выполнено |
| H9 | Импульсное чтение (ЭБУ ≤ 46) | N совпадает с LED импульсного счётчика | не выполнено |
| H10 | Стирание DTC на стендовом эталонном ЭБУ | трасса, verified = true, повтор чтения | не выполнено |

Результат аппаратного испытания оформляется issue по шаблону «Трасса / проверка на реальном
ЭБУ» с JSONL и осциллограммами. Только после этого функция получает статус 🚗 и профиль
ЭБУ — уровень VAL.

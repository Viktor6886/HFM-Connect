# Протокол диагностического обмена Bosch HFM-SFI (M104 / M111) по K-Line

Структурированный справочник HFM Connect. Сводит базовую спецификацию протокола REV 1.1,
дополнения REV 1.3/1.4 и заводскую документацию Mercedes-Benz. Реестр источников —
[SOURCES.md](SOURCES.md).

> **Статус.** Байтовые последовательности ниже относятся к реконструированной спецификации
> REV 1.1 (уровень «РЕК»), а не к заводскому документу. Заводские документы подтверждают
> функции, условия, нормы и процедуры, но не HEX. Проверка на реальном ЭБУ этим проектом
> ещё не проводилась.

## 0. Уровни подтверждения

| Метка | Смысл | Что разрешено в прошивке |
|---|---|---|
| **ЗАВ** | Прямо указано в заводском документе Mercedes-Benz | Нормы, условия, процедуры; не «готовый HEX» |
| **РЕК** | Реконструированные данные протокола (REV 1.1) | Чтение с guard по ID и RAW-логом; запись — карантин |
| **ГИП** | Правдоподобно, но неоднозначно | Только при явном opt-in «Экспериментальное чтение» |
| **VAL** | Полная трасса + повторяемое испытание на конкретном HW/SW/diag index | Пока **нет ни одной записи VAL** |
| **БЛОК** | Нет проверки, есть риск изменения состояния | Прошивка отвергает |

Классы доказательств формул (реестр Live Data): **AV** — наблюдалось на эталонном ЭБУ
013 545 13 32; **AH** — высоко вероятно; **AC** — кандидат.

## 2. Инициализация (профиль REV 1.1, РЕК)

```
parity = none; flush
BREAK: линия = 0 ........ 177 мс   (настраивается: Настройки → Тайминги K-Line)
пауза ................... 214 мс   (настраивается)
flush; parity = space
TX AA  →  RX AA (эхо) + 55 (ЭБУ)   иначе NO_SYNC
повтор до 3 раз с паузой 1,0 с
```

`KLineUart::wakeup()` формирует BREAK инверсией TXD (`uart_set_line_inverse`), потому что
`uart_write_bytes_with_break` ограничен 255 битовыми интервалами (~26,6 мс). При поиске
синхронизации допускается посторонний байт, оставшийся после фронта BREAK: ищется пара
`AA 55` среди первых 4 принятых байтов. Тайминги 177/214/750 мс — исходный профиль; на
конкретном адаптере их можно скорректировать без перепрошивки.

### 2.1 Пробуждение через USB-адаптер FTDI (KKL) — РЕК, по коду ПК-тестера

Реконструировано по машинному коду ПК-тестера, который работает с FT232RL-адаптером
владельца (процедура подключения 0x4935a4, приём байта 0x494f04, обёртки D2XX 0x4837a0…;
материалы анализа вне репозитория). Реализация — `KLineWake.cpp`, тесты —
`tests/host/test_kline_wake.cpp`.

| Шаг | ПК-тестер | Прошивка |
|---|---|---|
| Открытие | FT_Open → FT_SetFlowControl → FT_SetBaudRate(9600) → FT_SetDataCharacteristics(8, 1, без паритета) → FT_SetTimeouts → FT_SetLatencyTimer; **DTR/RTS не трогает** | SIO_RESET, FLOW 0, BAUD 9600, LATENCY, **DTR/RTS сняты**, PURGE, SET_DATA 8N1 |
| BREAK | FT_SetBreakOn, Sleep(165 мс; в настройках 160 или 130), FT_SetBreakOff | BREAK из настроек (177), автоподбор 165/160/130 |
| После BREAK | заново FT_SetBaudRate(9600) + паритет 4 (SPACE), Sleep(100) | SET_BAUDRATE + SET_DATA SPACE |
| AA | в момент t0 + 390 мс от начала BREAK | t0 + BREAK + пауза (177 + 214 = 391 мс) |
| Ответ | эхо AA от адаптера, затем инверсия 55 от ЭБУ, окно 800 мс; первый принятый 00 (сам BREAK) пропускается | так же |
| Без ответа | без нового BREAK: 00 через 1 с, 00 ещё через 1 с (при ответе FF — сразу дальше), затем AA | так же |

DTR/RTS: ПК-тестер вызывает FT_SetRts/FT_ClrRts только отдельной командой, при открытии
линии не меняет; вторая ПК-программа открывает COM-порт с `DTR_CONTROL_DISABLE` /
`RTS_CONTROL_DISABLE`. До 0.4.0 прошивка включала обе линии — расхождение исправлено
(D-026).

## 3. Модель транзакции

| Тип байта | Паритет | Ответ ЭБУ | Проверка в прошивке |
|---|---|---|---|
| Префикс (страница/опкод) | none | эхо + `ACK = prefix ^ 0xFF` | эхо и ACK, иначе ECHO_MISMATCH / BAD_ACK |
| Селектор (после префикса чтения) | space | эхо + 1 байт данных | эхо |
| Аргумент (после префикса записи) | space | эхо + ответ (обычно `~arg`) | эхо, ожидаемое значение |

- ЭБУ помнит последний префикс (контекст страницы). Прошивка отказывает селектору без
  валидного контекста чтения (`NOT_ALLOWED`).
- Межбайтовых пауз нет; дедлайн 750 мс на пару «эхо + ответ» (настраивается).
- Любая ошибка (эхо, ACK, тайм-аут) → сеанс `Error`, контекст сброшен, **без автоповтора**.

### 3.1 Политика команд (белый список, `classifyPrefix()`)

| Класс | Префиксы | Условие отправки |
|---|---|---|
| Чтение | `20` `21` `24` `27` `F0` `F1` | сеанс Ready |
| Эксп. чтение | `F9` (VIN), `12` `22` `23` (Live Data варианта VDO) | + `experimentalReads` |
| Запись | `10` `F3` `CF` `C1` `C0` `E0` `D0`–`D4` | + токен ServiceGuard (одна операция) |
| Неизвестно | всё остальное | **никогда** (перебор 00–FF запрещён: REV 1.1 с.6–7) |

Keep-alive `10 00` (1300 мс простоя) из REV 1.1 **не используется**: `10` входит в
последовательность стирания DTC. Keep-alive прошивки — чтение `F0:00` раз в 0,7 с (D-006,
D-021): с запасом к пределу простоя 1300 мс даже при задержках USB-адаптера.

## 5. Идентификация (F0) — РЕК

```
for i in 00..1B, 26, 27:  F0 (none) → 0F ;  i (space) → byte[i]
```

| Байты | Содержимое | Пример (синтетический блок тестов) |
|---|---|---|
| 0–1 | код производителя: байт 1 — буква (`B` Bosch, `V` VDO, `S` Siemens), байт 0 — группа системы (27/2C → 1, 21/23 → 2) | 2C 42 |
| 2–11 | ASCII-идентификатор «XX XXXXX XXX» | M2 28320 VR0 |
| 12–21 | номер ЭБУ, 10 цифр | 013 545 13 32 |
| 22–23 | дата HW, неделя/год (BCD) | 35/92 |
| 24–25 | дата SW, неделя/год (BCD) | 46/92 |
| 26–27 | диагностический индекс `%02X/%02X` | 41/00 |
| F0:26, F0:27 | страница ПЗУ и адрес таблицы дескрипторов Live Data | читаются отдельно, необязательно |

Диагностический индекс трактуется как BCD (0x41 → 41) — ГИП, согласуется с диапазонами
40–44 и 45–59 (HFM), 60–79 (PMS). Производитель определяется так же, как в ПК-тестере
(процедура 0x4810f4): по букве во 2-м байте, независимо от 1-го байта (РЕК, D-028); до 0.5.0
Bosch признавался только при `2C 42`. Не путать: diag index
ЭБУ ≠ «diagnosis version» заводского тестера (42/45/46/49) ≠ «Diag Index 2/3» Trisco
(REV 1.4 §48). Чтение F0:26/27 необязательно: при ошибке сеанс переинициализируется, ID
остаётся действительным.

## 6. Память неисправностей (F1) — РЕК

```
for idx in 00..1F:  F1 (none) → 0E ;  idx (space) → битовая карта (1 байт)
```

### 6.1 Банки: текущие и сохранённые

Банк A = 00–0F, банк B = 10–1F. Источники REV 1.1 расходятся в том, какой банк
«текущий» (вопрос C-01). Прошивка определяет назначение в таком порядке:

1. **Правило OEM (ЗАВ)** — Engine 104/111 Diagnostic Manual 11/3: перемежающиеся
   неисправности (плохой контакт) «могут появляться только как сохранённые и никогда как
   текущие». Если в чтении установлены коды перемежающихся неисправностей (005, 008, 013,
   016, 019, 078 и др.) только в одном банке — этот банк сохранённый. Определение
   выполняется автоматически при каждом чтении (`dtc::inferBankMapping`).
2. **Профиль эталонного ЭБУ (РЕК)** — A = сохранённые, B = текущие.
3. Иначе — нейтральные метки «Банк A (F1 00–0F) / Банк B (F1 10–1F)». С 0.6.0 предположение
   профиля общего Bosch (ГИП) больше не превращается в подписи «текущие/сохранённые»
   (REV 1.2 E-06: не маркировать банк без подтверждения для diag index; D-030).

Текущие неисправности имеют смысл только при работающем двигателе: при включённом
зажигании и остановленном двигателе часть из них появляется закономерно (сторонний
справочник mb_dtc_adapt1, согласуется с OEM 11/3).

### 6.2 Декодирование

- Позиция бита: `pos = (idx mod 16)·8 + bit + 1` (bit 0 = LSB); `dtc = BASE[pos-1]`
  (152 элемента). Позиции 129–152 недостижимы при 16 байтах на банк (F1 30–32/40–42 —
  ГИП, только эксп. режим).
- **Заводские карты вариантов (D-022, ЗАВ-шаблоны тестера).** Заводской тестер выбирает
  одну из 7 карт «позиция → код» по числу цилиндров, производителю ЭБУ (B = Bosch,
  V = VDO) и байту идентификатора диагностики F0:26, сравниваемому с `'I'` (0x49) и `'P'` (0x50):

  | Карта | Цил. | Произв. | F0:26 |
  |---|---|---|---|
  | C86E | 4 | V/B | < 'I' |
  | C8EE | 6 | V/B | < 'I' |
  | C96E | 4 | V | 'I'…'O' |
  | CB9E | 4 | V | ≥ 'P' |
  | CA9E | 4 | B | ≥ 'I' |
  | CA06 | 6 | V | ≥ 'I' |
  | CB1E | 6 | B | ≥ 'I' |

  Данные — `data/protocol/dtc_variant_maps.json` → `DtcVariantMaps.h`. Значение 0 в карте —
  позиция не используется (бит показывается RAW). Число цилиндров берётся из выбранного
  автомобиля (M104 = 6, M111 = 4); производитель — из F0:00–01 (`2C 42` = Bosch).
- **Без карты** (автомобиль не выбран) — базовая таблица и ремапы, ключ которых —
  **позиция бита** (не код; ранее ошибочно применялись к коду), последовательно:
  1. 4 цилиндра: позиции 51→55 … 56→60
  2. `F0:26 == 'I'`, Bosch, не 4 цил.: 35→45, 36→46, 37→41, 38→42, 39→47, 40→48, 41→39, 42→40
  3. `F0:26 ≥ 'I'`: 70→122, 71→121, 74→120
  4. `'P' ≤ F0:26 ≤ 'U'`: 68→145, 69→146, 70→147, 93→148, …, 152→164
  Там, где карта и ремапы расходятся, приоритет у карты.
- Каталог: 165 записей (121/122 — только для версий вне США, unverified) (`data/protocol/dtc.csv`), статусы oem_supported / reference_supported
  / reconciliation_required / unverified. Коды вне каталога (239, 240, 243, 244, 247,
  253–255) показываются RAW.
- **M111**: коды 045–048, 061–063, 068/069, 093–096 не используются; пары катушек — T1/1
  цилиндры 1/4, T1/2 цилиндры 2/3 (Engine 111 11/10–11/12, ЗАВ). При выбранном автомобиле
  с M111 прошивка показывает эти тексты вместо текстов M104.
- Семантика памяти (WIS GF07.51-P-3017D, ЗАВ): постоянные, длительные (> 3 с) и
  прерывистые (5 раз за поездку) неисправности; сохраняются при отключении АКБ;
  стираются автоматически через 19 поездок без повтора. Поездка: > 4 км/ч, > 700 об/мин,
  зажигание выключено > 30 с.
- При обрыве/КЗ датчиков ОЖ, IAT, HFM ЭБУ подставляет замещающее значение, близкое к
  реальному; неисправность видна только в памяти DTC (OEM 11/3) — WebUI помечает такие
  параметры в Live Data.

### 6.3 Стирание — РЕК, карантин

```
предусловие: полный скан 00..0F, есть ненулевые байты; пауза 200 мс
10→EF 00→FF  200 мс | F3→0C FF→00  50 мс | 10→EF 00→FF 500 мс
10→EF 00→FF  200 мс | F3→0C FF→00  50 мс | 10→EF 00→FF 500 мс | 10→EF 00→FF
проверка: скан 00..1F, «verified» только если все 32 байта = 00
```

### 6.4 Импульсная диагностика (blink-code) — ЗАВ

Engine 104/111 11/5: чтение — замкнуть контакт 2–4 с, считать вспышки, повторять до
повтора первого кода; очистка — после показа кода удерживать 6–8 с (Bosch до 08/93:
5–6 с); reset — 6–8 с, OFF ≥ 2 с, ON ≥ 10 с. Только diagnosis version ≤ 46; с 49 — только
заводской тестер. Не для модели 210. Номера N существуют до конца MY1995.

Соответствие N → трёхзначный код (таблицы 11/8–11/15, `ImpulseDecoder.cpp`), выборочно:

| 2 | 002–005 | 18, 19 | 045–048 (только M104) | 33 | 081, 082 |
| 3 | 006–008 | 20 | 049–054 | 34 | 083, 084 |
| 4 | 009, 010 | 21 | 061–063 (только M104) | 35 | 085 |

## 8. Адаптации и кодировка — РЕК (AC)

| Функция | Рецепт | Формула |
|---|---|---|
| Адаптация ХХ (аддитивная) | `24* 90` | trunc0(275·r − 35000, 1000)/10 кг/ч (Bosch; VDO — % — формула не подтверждена → RAW) |
| Нижняя частичная нагрузка | `24* 92` | (trunc0(390625·r − 5·10⁷, 10⁶) + 100)/100 |
| Верхняя частичная нагрузка | `24* 93` | то же |
| Кодировка | `27* 02 24* F0` | c, m → КПП, ступени, катализатор, USA, EFP, DM, упоры, «экран» |

`*` — префикс (parity none). 9-значный код комплектации (меню 6 «Version coding»
заводского тестера) **не восстановлен**. Справочно (mb_dtc_adapt1, сторонний): предел
аддитивной коррекции на ХХ ±1,0 мс, мультипликативной ±32 %.

### 8.1 Сброс адаптаций — РЕК, карантин

```
условия: зажигание ВКЛ, 20:B7 = 00; бэкап DTC и адаптаций
CF*(→30) FF(→00)  C1*(→3E) FC(→03)    ← вход: ответы 00 и 03, иначе прервать
E0*(→1F) 00   CF*(→30) 00   C0*(→3F) FC
затем обязателен цикл зажигания; результат ЭБУ не подтверждает
```

### 8.2 Тест клапана продувки Y58/1 — РЕК, карантин

```
условия: 400–1500 об/мин, ОЖ 80–110 °C
вход:    CF* FF  C1* FC (00/03) → 96 (бит 0x40) → D0* 0F → 96 → D4* 00
ON:      96 (бит 0x40) → D4* 1A        OFF: 96 → D4* 00
лимит ON 30 с (таймер прошивки), затем восстановление
restore: 96 → D0* 0B D1* 00 D2* 00 D3* 40 D4* 00 (+ D0* 0F, если зонд отправлялся)
```

## 9. Ошибки и восстановление

| Ситуация | Поведение прошивки |
|---|---|
| Нет AA 55 | до 3 попыток; перед каждым BREAK линия молчит 2,5 с + 1 с за каждую неудачу (до +4 с); затем `Error` |
| Эхо ≠ TX / ACK ≠ ~prefix / тайм-аут | сеанс `Error`, контекст сброшен; команда не повторяется |
| Ошибка при чтении (Live Data, keep-alive) | ресинхронизация чтения: пауза 300 мс, префикс `F0` → эхо + ACK `0F`, сеанс продолжается без BREAK; иначе тишина и новое пробуждение; опрос Live Data продолжается сам |
| Связь восстановлена автоматически | память неисправностей F1 читается заново (только чтение, настройка; D-033): не чаще раза в 3 с после неудачи, не более 3 неудач подряд, остановка при двух обрывах подряд сразу после такого чтения; не выполняется после FAULT_STOP и во время сервисной операции |
| После префикса записи в сеансе | ресинхронизация запрещена — только новое пробуждение и идентификация |
| Ошибка при записи | `FAULT_STOP`: запись блокирована до квитирования, переподключения и повторной идентификации |
| Ошибки паритета/кадра UART | считаются и показываются; байт не отбрасывается |
| Простой UART | драйвер остаётся установленным, TX удерживается в «1» (нет плавающего входа трансивера) |

### 9.1 Почему тишина перед BREAK (D-027) — ГИП

ПК-тестер поддерживает сеанс байтом каждые 1300 мс (`IDLE_TIME`), значит ЭБУ держит сеанс
дольше 1,3 с без обмена. Пока сеанс ЭБУ не истёк, BREAK и AA принимаются им как байты
сеанса, и 55 не приходит. Прежняя прошивка будила ЭБУ сразу после ошибки байта и каждую
секунду повторяла BREAK/AA/00/00/AA — эти байты продлевали сеанс ЭБУ, отсюда NO_SYNC и
восстановление «через минуту». Теперь перед каждым BREAK соблюдается тишина (2,5 с + 1 с
за неудачу). Точный тайм-аут сеанса ЭБУ в документации не указан.

Ресинхронизация чтения (`HfmSession::resync`) — проектное решение: префикс `F0` — команда
чтения из белого списка (9-й бит = 1), ответ `0F` подтверждает, что ЭБУ в сеансе. Не
применяется, если в сеансе был префикс записи или взведён токен ServiceGuard.

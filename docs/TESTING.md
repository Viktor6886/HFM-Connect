# Методика испытаний

Испытания делятся на **программные** (без ЭБУ) и **аппаратные** (автомобиль/стенд).
Программные испытания подтверждают внутреннюю согласованность с реконструированным
протоколом, но **не** поведение реального ЭБУ. Не смешивать результаты.

## 1. Программные испытания (автоматические)

| Набор | Команда | Что проверяет |
|---|---|---|
| Host-тесты C++ | `python tools/run_host_tests.py` | декодеры (тест-векторы), ID, DTC/ремапы/каталог, профили и capability, сеанс на SimEcu (BREAK/SYNC/эхо/ACK/тайм-аут), политика команд, Live Data и нормы, адаптации/кодировка, ServiceGuard, карантинные рецепты, журнал JSONL, импульсный декодер, replay трассы |
| Сверка таблиц | `python tools/check_tables.py` | LUT 256×2, маски, базовые коды, ремапы, каталог DTC = данные анализа |
| WebUI | `python tools/build_webui.py --check`, `node --check webui/app.js` | бандл актуален, синтаксис JS |
| Прошивка | `arduino-cli compile … firmware/HFMConnect` | компиляция для ESP32-S3 |
| CI | `.github/workflows/ci.yml` | всё перечисленное при каждом push/PR |

### Трассы

- `tests/traces/sim_*.jsonl` — **синтетические** трассы, записанные с тестовой моделью ЭБУ (transport
  `sim`). Пересоздание: `HFM_REGEN_TRACES=1 python tools/run_host_tests.py golden`.
- `tests/traces/ecu_*.jsonl` — место для трасс реальных ЭБУ (пока нет). Каждая трасса
  проигрывается тем же `ReplayLink`; формат — `/api/trace.jsonl`.

### Сценарии отказов (покрыты тестами)

нет синхронизации (3 попытки) · несовпадение эха · неверный ACK · тайм-аут с частичным
приёмом · неизвестный префикс · запись без токена · селектор без контекста · неполный цикл
(MAF-пара отбрасывается) · просроченный/повторный токен · неверная фраза · смена ЭБУ между
prepare и execute · разомкнутый WRITE-EN · неизвестное напряжение · устаревшие обороты ·
FAULT_STOP до квитирования · расхождение запроса с трассой.

## Проверка USB в 0.3.7 на ESP32-S3 Zero

Проверить напрямую и через хаб 214B:7260 с внешним питанием.

| Сценарий | Что проверить в разделе «Подключение» |
|---|---|
| Включить ESP32 с уже вставленным KKL | Появляется FT232R 0403:6001, счётчик подключений увеличивается |
| Загрузить ESP32 с пустым портом, затем вставить KKL | Такое же обнаружение без перезагрузки и ручного поиска |
| Подключить хаб после загрузки ESP32 с уже вставленным KKL, затем переставить KKL в другой порт | Появляется FTDI, отображается новый порт |
| Вынуть KKL во время чтения и вставить обратно | Старый сеанс завершается, счётчик подключений растёт, инициируется новая синхронизация при включённом автоподключении |
| Получить CHECK_SHORT_DEV_DESC FAILED и оставить оборудование подключённым более минуты | После пятой неудачной попытки журнал показывает повторы примерно раз в 30 с до обнаружения FTDI |
| Отключить автосоединение вручную, переподключить USB | FTDI определяется, запуск сеанса ЭБУ ждёт кнопки «Подключить» |

Для USB достаточно устойчивого 0403:6001. Для проверки сеанса с запитанным ЭБУ нужны AA 55 и успешное чтение идентификации. Сохранить USB-журнал и RAW-трассу для каждого сбоя.

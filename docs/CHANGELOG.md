# История изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии прошивки — `HFM_FW_VERSION`.

## [0.8.1] — 2026-11-12

### Изменено (D-033)
- После автоматического восстановления связи память неисправностей читается заново
  (только чтение F1, настройка «Читать ошибки при подключении»): дисплей, WebUI и
  светодиод показывают результат текущего соединения, метка «устарело» остаётся только
  если автоматическое чтение выключено или не удалось.
- Защита от зацикливания на плохой линии: повтор неудачного чтения не чаще раза в 3 с и
  не более 3 раз; остановка, если связь дважды подряд пропадает сразу после такого чтения.
- Сигнал «есть/нет ошибок» после автоматического перечитывания звучит только при
  изменении содержимого памяти.
- В разделе «Ошибки» у автоматически выполненного чтения пометка «автоматически».

### Исправлено
- Если ЭБУ не ответил на экспериментальные байты F1 30–32/40–42, сеанс чтения
  возобновляется сразу (раньше связь уходила в восстановление), а результат попытки
  отмечается в матрице возможностей.

## [0.8.0] — 2026-11-12

### Добавлено (OLED-дисплей, D-032)
- OLED 0,96" 128×64 I²C (SSD1306 / SH1106, U8g2): заставка с автомобилем, состояния связи
  с пиктограммами, анимированные смайлики «Ошибок нет» / «Есть ошибки!», циклический показ
  ошибок (крупный код, счётчик, описание с переносом и плавной прокруткой), экраны потери
  связи и ошибки чтения; русские тексты, Ё/ё.
- Дисплей — отдельная задача низкого приоритета, только читает состояние; при отсутствии
  или отказе дисплея сканер работает без изменений.
- Настройки «Дисплей OLED»: включение, контроллер, поворот на 180°, яркость; автоприглушение
  неподвижной картинки.
- `tools/oled_preview.py` — рендер экранов на ПК; `tools/gen_oled_bitmaps.py` — изображения.

### Изменено
- Сборка с дисплеем требует библиотеку U8g2 и схему разделов **Huge APP**; без дисплея
  (`HFM_OLED_ENABLE 0`) — как раньше.

## [0.7.0] — 2026-11-11

### Добавлено (индикация, D-031)
- Звук на пассивном пьезоизлучателе (GPIO8): мелодии подключения, восстановления,
  отключения, обрыва связи, подключения адаптера, «ошибок нет» / «есть ошибки», FAULT_STOP;
  мягкая атака и затухание, громкость в настройках.
- Внешний RGB-светодиод с общим катодом (GPIO5/6/7): сцены состояния с плавным
  «дыханием», вспышки опроса Live Data, двойная янтарная вспышка при наличии ошибок;
  яркость в настройках; встроенный RGB платы повторяет цвета.
- Настройки «Индикация»: громкость, яркость, проверка звука и цветов; «Читать ошибки при
  подключении» (по умолчанию включено, только чтение). `POST /api/indicator/test`.

### Исправлено
- Встроенный RGB-светодиод ESP32-S3 Zero (GPIO21) не светил при плате «ESP32S3 Dev Module»
  (код писал в GPIO48) — вывод задаётся `HFM_ONBOARD_RGB_PIN`.
- Подготовленный, но не выполненный план сервисной операции навсегда оставлял
  `ServiceGuard` в PREPARED и блокировал автоматическое восстановление связи; теперь план
  истекает через 20 с и отменяется при потере связи.
- «Подключить» сообщал об успехе, если связь оборвалась сразу после идентификации.

## [0.6.0] — 2026-11-11

### Добавлено (справочник HFM-SFI M104/M111, D-030)
- Карточки ошибок: под каждой ошибкой надпись «карточка ошибки»; карточка плавно раскрывается
  прямо под ней (повторное нажатие — сворачивает, по умолчанию закрыты): расшифровка,
  возможные причины, порядок проверки, что наблюдать в Live Data, применимость к карте
  вашего ЭБУ, цепочка «бит → карта → ремап → код», контекстные правила HHT, источник и
  уровень достоверности, особые предупреждения (075, 136, 145–164, 150, 156/157).
- Карточки параметров Live Data и адаптаций («карточка параметра»): смысл, текущая оценка с
  причинами отклонения, ожидаемое поведение, заводские нормы (строка вашего двигателя
  выделена), формулы и способы получения из 42 записей источников, кнопка графика.
- Раздел «Справочник кодов»: HFM цифровые (поиск, фильтр по карте ЭБУ), импульсные,
  DM N59/1, CC/ISC N4/3, ошибки HFM Connect — каждый с карточкой.
- Раздел «Диагностика по симптомам»: 20 сценариев и 14 правил качества данных.
- Подключение: карточка текущей ошибки связи (HFM-TR-001…012).
- Ошибки: отметка «новая» для кодов, которых не было в предыдущем чтении.
- Live Data: заводские нормы, которые устройство не читает (ДМРВ, продувка, масло).

### Изменено
- Тексты кодов 107 и 117 — по заводскому руководству; 33 кода получили предварительные
  расшифровки (статус «предварительно (HHT)», не подтверждено на ЭБУ).
- Банки F1 без подтверждения подписываются «Банк A / Банк B» (REV 1.2 E-06).
- `/ref.json` — справочник в прошивке (gzip ≈ 43 КБ); `tools/import_reference.py`.

## [0.5.0] — 2026-11-10

### Исправлено (обрывы связи и NO_SYNC, D-027)
- После ошибки байта ЭБУ больше не будится сразу: перед каждым BREAK линия молчит 2,5 с
  (+1 с за каждую неудачу), чтобы ЭБУ закрыл свой сеанс; раньше повторные BREAK/AA продлевали
  его, и восстановление занимало до минуты.
- Ошибка чтения (Live Data, keep-alive) сначала лечится ресинхронизацией F0 → 0F без нового
  пробуждения; после префикса записи — никогда.
- «Подключить» при готовом сеансе его не разрывает; задания встают в очередь (6), повторные
  объединяются — «Устройство занято другой операцией» больше не появляется.
- Автоподбор не уходит с профиля, который уже разбудил ЭБУ; профиль хранится в NVS.
- ЭБУ, не отвечающий на F0:26/27, запоминается — подключение больше не обрывается после
  идентификации.
- Неудачный цикл Live Data не затирает последние значения; отчёт показывает последний снимок
  с его возрастом.
- Опрос Live Data продолжается сам после восстановления связи и после переподключения адаптера.

### Изменено
- Производитель ЭБУ — по букве во 2-м байте F0, как в ПК-тестере (D-028): `B` Bosch, `V` VDO.
- Одно состояние связи для всего интерфейса (D-029); баннер «восстанавливаю автоматически».
- Wi-Fi: точка доступа «HFM Connect», пароль по умолчанию `12345678`.
- Тема, параметры графика Live Data и 9-значный код хранятся в устройстве (NVS).
- WebUI: запросы с тайм-аутом и без наложения, обновление без перерисовки всей страницы,
  пометка устаревших данных, восстановление после потери Wi-Fi.
- Главная: карточки ЭБУ (номер, идентификатор), памяти неисправностей и автомобиля; внизу —
  версия и время работы.
- Подключение: только адаптер, автоподключение, время на связи и WRITE-EN; журнал TX/RX
  удобен на телефоне; исправлен вывод HTML-кода в строках результата.
- Live Data: три кнопки равной ширины; норма в карточке, красные стрелки ↓/↑ и пульсирующая
  красная рамка при подтверждённом отклонении; отметка параметров графика видна отдельно.
- Убраны технические пояснения и блоки: USB-диагностика, «Пробуждение ЭБУ», RAW F0,
  импульсный считыватель на странице «Ошибки» (настройки сохранены), «Безопасность»,
  «Оборудование», перезагрузка, «Напряжение ≥ 11 В» в настройках (проверка осталась в
  диалоге операции).
- Матрица возможностей показывает фактический результат (работает / ошибка / не выполнялось).
- Мастер ввода в эксплуатацию: шаги по данным, «Прочитать всё и сохранить снимок «до»».

### Добавлено
- `GET /api/job?id=` — результат конкретного задания; `link`, `link_text` в `/api/status`.
- `tools/dev_server.py` — просмотр WebUI без устройства (синтетические данные).
- Host-тесты: тишина перед BREAK, ресинхронизация, запрет после записи, рабочий профиль,
  производитель по букве.

## [0.4.0] — 2026-11-10

### Изменено (подключение к KKL-адаптеру переработано, D-026)
- **DTR и RTS адаптера теперь выключены**, как у ПК-программ, с которыми адаптер работает
  (раньше прошивка включала обе линии). Режим можно выбрать в настройках.
- Новое пробуждение ЭБУ (`KLineWake`) по коду ПК-тестера: BREAK → заново 9600 Бод + SPACE →
  AA через 390 мс от начала BREAK → ожидание эха AA и ответа 55 (800 мс); при молчании без
  нового BREAK отправляются 00, 00 и снова AA с интервалом 1 с.
- Автоподбор: пока ЭБУ молчит, следующие попытки идут с BREAK 165/160/130 мс и разными
  DTR/RTS; рабочий профиль сохраняется.
- Корневой USB-порт включается через 1,5 с после старта — хаб и FT232RL успевают
  включиться до первого запроса.

### Добавлено
- Блок «Пробуждение ЭБУ» на странице *Подключение*: дошёл ли BREAK до линии, есть ли эхо
  AA, ответ ЭБУ, переданные и принятые байты, профиль следующей попытки; `adapter.wake` в
  `/api/status`; строки `wake …` в журнале USB.
- Сообщение об ошибке подключения указывает, что именно не так: линия молчит / нет эха /
  адаптер в порядке, ЭБУ не ответил.
- Настройки: «DTR / RTS адаптера FTDI», «Автоподбор».
- 8 host-тестов пробуждения (`test_kline_wake.cpp`).

## [0.3.7] — 2026-11-10

- Клиент USB регистрируется до включения корневого порта. Событие подключения и периодический опрос запускают обход доступных адресов.
- После сбоя перечисления таймер продолжает восстановление без новых ошибок стека. После пятой попытки интервал составляет 30 с. При рабочем адаптере сбросы прекращаются.
- Состояние FTDI публикуется после запуска bulk IN. Завершение старых операций синхронизировано с освобождением USB-интерфейса. После переподключения начинается новый сеанс HFM с учётом настройки автоподключения.

## [0.3.6] — 2026-11-09

## [0.3.5] — 2026-11-09

### Изменено

  уходят, эхо `AA` принимается. Ответа ЭБУ `55` нет (NO_SYNC) — сторона автомобиля.

## [0.3.4] — 2026-11-09

### Исправлено
- Адаптер за USB-хабом не определялся после одного сбоя: ESP-IDF при ошибке первого
  запроса к устройству (`ENUM: CHECK_SHORT_DEV_DESC FAILED`) отключает порт хаба
  (`EXT_PORT: Port disabled`) и не повторяет. Теперь прошивка видит это в журнале USB-стека
  и переопределяет устройства: выключает/включает корневой порт
  (`usb_host_lib_set_root_port_power`), до 5 попыток с паузой 1,5 с; счётчик сбрасывается
  при подключении адаптера.

### Добавлено
- Кнопка «Переопределить USB-устройства» (`POST /api/usb/reset`), счётчики
  `enum_failures`, `reenum_count` в `/api/usb`.

## [0.3.3] — 2026-11-09

### Добавлено
- `/api/usb` и блок «USB-диагностика» на странице *Подключение*: все определённые

### Исправлено

## [0.3.2] — 2026-11-09

### Добавлено
- Электрическая диагностика USB-порта: маршрут внутреннего PHY на OTG (RTC_CNTL_USB_CONF,
  USB_WRAP), состояние корневого порта (HPRT: питание, подключение, уровни D+/D−) — на
  странице *Подключение* и в `/api/status` (`phy_otg`, `port_connected`, `dp`, `dm`).
  «D+/D− без сигнала» однозначно означает, что FTDI-чип не подтянул D+: нет 5 В VBUS на
  адаптере или он не в разъёме USB (OTG).

### Исправлено
- Причина «не обнаружен» обрезалась («…или ад»): буферы причины 160 Б, сообщений 256 Б,
  тексты сокращены.
- Страница *Подключение* называла транспорт «Адаптер K-Line на UART».

## [0.3.1] — 2026-11-09

### Исправлено
- FTDI-адаптер, уже подключённый при включении, мог не определиться никогда: событие
  USB «новое устройство» приходило до регистрации клиента. Теперь уже определённые
  USB-устройства опрашиваются явно (раз в 1 с, пока адаптера нет).
- Сообщения длиннее 96 байт обрезались посреди русской буквы («…кабель и пит?»): буферы
  сообщений увеличены до 192 байт, JSON отбрасывает неполные UTF-8 последовательности.

### Добавлено
- Диагностика USB: причина «адаптер не обнаружен» (нет USB-устройств — нет 5 В VBUS или
  не тот разъём; найдено устройство не FTDI с его VID:PID; ошибка захвата интерфейса;
  ошибка запуска USB-хоста), число устройств на разъёме, последнее VID:PID — на странице
  *Подключение*, в `/api/status` (`adapter.note`, `usb_devices`, `dev_events`,
  `seen_vid_pid`) и в журнале Serial (`[usb] …`, 115200 Бод, разъём UART/COM).

## [0.2.0] — 2026-11-08

### Изменено
- Режим симулятора удалён из прошивки и WebUI: только реальная K-Line (D-016). Модель ЭБУ
  осталась в `tests/host/` для автоматических тестов; mock-сервер удалён.
- UART-драйвер K-Line устанавливается при старте и не удаляется: TX удерживается в «1».
- Синхронизация ищет `AA 55` среди первых 4 байт после BREAK.
- Тексты репозитория: ссылки на спецификацию REV 1.1–1.4 и заводские документы (D-017);
  данные перенесены в `data/protocol/` (без служебных ссылок), спецификации не публикуются.

### Добавлено
- Тайминги K-Line (BREAK / пауза / тайм-аут) настраиваются в WebUI и хранятся в NVS (D-019).
- Чтение F0:26/27 (страница ПЗУ, адрес дескрипторов Live Data).
- Автоопределение банков DTC по заводскому правилу «перемежающиеся — только сохранённые» (D-018).
- Заводские таблицы импульсных кодов N → трёхзначный код для M104 и M111 (D-020).
- Тексты кодов M111 (4 цилиндра, пары катушек 1/4 и 2/3).
- Пометка возможных замещающих значений ОЖ/IAT/HFM в Live Data при DTC датчика.
- Справочник проверок датчиков ОЖ B11/3 и IAT B17 (напряжение/сопротивление, OEM).
- Подсказка о смысле текущих неисправностей только при работающем двигателе.

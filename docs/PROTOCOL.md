# Протокол диагностического обмена Bosch HFM-SFI (M104 / M111) по K-Line

Структурированный справочник для разработки HFM Connect. Сводит данные базового протокола
REV 1.1, дополнений REV 1.3/1.4, отчётов анализа HFMreader 1.1.1 / HFMScan / HHTwin и
заводской документации Mercedes-Benz. Полные исходники — `docs/specs/`, реестр источников —
[SOURCES.md](SOURCES.md).

> **Статус.** Байтовые последовательности ниже **реконструированы из программ**, а не взяты
> из заводской документации. Ни одна последовательность не проверялась этим проектом на
> реальном ЭБУ. Заводские документы подтверждают функции, условия и нормы, но не HEX.

## 0. Уровни подтверждения

| Метка | Смысл | Что разрешено в прошивке |
|---|---|---|
| **ЗАВ** | Прямо указано в заводском документе Mercedes-Benz | Нормы, условия, процедуры; не «готовый HEX» |
| **РЕК** | Реконструировано из HFMreader/HFMScan/HHT (REV 1.1) | Чтение с guard по ID и RAW-логом; запись — карантин |
| **ГИП** | Правдоподобно, но неоднозначно | Только при явном opt-in «Экспериментальное чтение» |
| **VAL** | Полная трасса + повторяемое испытание на конкретном HW/SW/diag index | Пока **нет ни одной записи VAL** |
| **БЛОК** | Нет проверки, есть риск изменения состояния | Прошивка отвергает |

Классы доказательств HFMreader (сохраняются в реестре Live Data): **AV** — автор пометил
VERIFIED на ЭБУ 013 545 13 32; **AH** — «высоко вероятно»; **AC** — кандидат.

## 2. Инициализация (профиль «R», HFMreader serial_transport, РЕК)

```
parity = none; flush
BREAK: линия = 0 ........ 177 мс
пауза ................... 214 мс
flush; parity = space
TX AA  →  RX AA (эхо) + 55 (ЭБУ)       иначе NO_SYNC
повтор до 3 раз с паузой 1,0 с (reader_service)
```

Реализация: `KLineUart::wakeup()` — BREAK через инверсию TXD (`uart_set_line_inverse`), т.к.
`uart_write_bytes_with_break` ограничен 255 битовыми интервалами (~26,6 мс).
Длительности 177/214 мс — профиль одной программы; **реальные границы не измерены** (issue «oscillogram»).

## 3. Модель транзакции

| Тип байта | Паритет | Ответ ЭБУ | Проверка в прошивке |
|---|---|---|---|
| Префикс (страница/опкод) | none | эхо + `ACK = prefix ^ 0xFF` | эхо и ACK, иначе ECHO_MISMATCH / BAD_ACK |
| Селектор (после префикса чтения) | space | эхо + 1 байт данных | эхо |
| Аргумент (после префикса записи) | space | эхо + ответ (обычно `~arg`) | эхо, ожидаемое значение |

- ЭБУ помнит последний префикс (контекст страницы). Прошивка отказывает селектору без
  валидного контекста чтения (`NOT_ALLOWED`).
- Межбайтовых пауз HFMreader не задаёт; дедлайн 750 мс на пару «эхо + ответ».
- Любая ошибка (эхо, ACK, тайм-аут) → сеанс `Error`, контекст сброшен, **без автоповтора**.

### 3.1 Политика команд (белый список, `classifyPrefix()`)

| Класс | Префиксы | Условие отправки |
|---|---|---|
| Чтение | `20` `21` `24` `27` `F0` `F1` | сеанс Ready |
| Эксп. чтение | `F9` (VIN) | + `experimentalReads` |
| Запись | `10` `F3` `CF` `C1` `C0` `E0` `D0`–`D4` | + токен ServiceGuard (одна операция) |
| Неизвестно | всё остальное | **никогда** (перебор 00–FF запрещён: REV 1.1 с.6–7) |

`10 00` как keep-alive (HFMScan IDLE_CMD, 1300 мс) **не используется**: `10` входит в
последовательность стирания DTC. Keep-alive прошивки — чтение `F0:00` раз в 1 с (D-006).

## 5. Идентификация (F0 00–1B, 28 байт) — РЕК

```
for i in 00..1B:  F0 (none) → 0F ;  i (space) → byte[i]
```

| Байты | Содержимое | Пример (синтетический симулятор HFMreader) |
|---|---|---|
| 0–1 | производитель, `2C 42` = BOSCH | 2C 42 |
| 2–11 | ASCII-идентификатор «XX XXXXX XXX» | M2 28320 VR0 |
| 12–21 | номер ЭБУ, 10 цифр | 013 545 13 32 |
| 22–23 | дата HW, неделя/год (BCD) | 35/92 |
| 24–25 | дата SW, неделя/год (BCD) | 46/92 |
| 26–27 | диагностический индекс `%02X/%02X` | 41/00 |

Диагностический индекс трактуется как BCD (0x41 → 41) — ГИП, согласуется с диапазонами
HFMScan (40–44 и 45–59 — HFM, 60–79 — PMS). Код производителя VDO неизвестен.
Не путать: diag index ЭБУ ≠ «HHT diagnosis version» (42/45/46/49) ≠ «Diag Index 2/3» Trisco (REV 1.4 §48).

## 6. Память неисправностей (F1) — РЕК

```
for idx in 00..1F:  F1 (none) → 0E ;  idx (space) → битовая карта (1 байт)
```

- Банк A = 00–0F, банк B = 10–1F. **Какой из них «текущие», а какой «сохранённые» —
  открытый вопрос C-01**: HFMreader — A = stored, B = current; HFMScan — A = current, B = stored.
  Прошивка использует нейтральные метки, пока профиль ЭБУ не утверждает отображение
  (эталонный ЭБУ — по HFMreader, уровень РЕК).
- Позиция бита: `pos = (idx mod 16)·8 + bit + 1` (bit 0 = LSB); `dtc = BASE[pos-1]`
  (152 элемента). Позиции 129–152 недостижимы при 16 байтах на банк (HFMScan читает
  30–32/40–42 — ГИП, только эксп. режим).
- Ремапы по варианту — **последовательно** (`value = map.get(value, value)`, подтверждено
  байткодом `apply_variant_remaps` L89–104):
  1. `engine_group == 'o'`: 51→55 … 56→60
  2. `diag == 49 && Bosch && group 'h'`: 35→45, 36→46, 37→41, 38→42, 39→47, 40→48, 41→39, 42→40
  3. `diag ≥ 49`: 70→122, 71→121, 74→120
  4. `50 ≤ diag ≤ 55`: 68→145, 69→146, 70→147(недостижимо после п.3), 93→148, …, 152→164
- Каталог: 163 записи (`data/hfmreader/dtc.csv`), статусы oem_supported / reference_supported
  / reconciliation_required / unverified. Коды вне каталога (239, 240, 243, 244, 247, 253–255)
  показываются RAW.
- Заводская семантика памяти (WIS GF07.51-P-3017D): фиксируются постоянные, длительные
  (> 3 с) и прерывистые (5 раз за поездку) неисправности; сохраняются при отключении АКБ;
  автоматически стираются через 19 поездок без повтора — **ЗАВ**.

### 6.1 Стирание (HFMreader DtcClearProtocol) — РЕК, карантин

```
предусловие: полный скан 00..0F, есть ненулевые байты; пауза 200 мс
10→EF 00→FF  200 мс | F3→0C FF→00  50 мс | 10→EF 00→FF 500 мс
10→EF 00→FF  200 мс | F3→0C FF→00  50 мс | 10→EF 00→FF 500 мс | 10→EF 00→FF
проверка: скан 00..1F, «verified» только если все 32 байта = 00
```

### 6.2 Импульсная диагностика (blink-code) — ЗАВ (процедура), ГИП (тайминги импульсов)

OEM Engine 111 11/5: чтение — замкнуть контакт 2–4 с, считать вспышки, повторять до повтора
первого кода; очистка — после показа кода удерживать 6–8 с (Bosch до 08/93: 5–6 с); reset —
6–8 с, OFF ≥ 2 с, ON ≥ 10 с. Только HHT diagnosis ≤ 46; с 49 — только HHT. Не для модели 210.
Номер N ≠ трёхзначный код A. Ширина импульсов в документах не указана.

## 8. Адаптации и кодировка — РЕК (AC)

| Функция | Рецепт | Формула |
|---|---|---|
| Адаптация ХХ (аддитивная) | `24* 90` | trunc0(275·r − 35000, 1000)/10 кг/ч (Bosch; VDO — % — формула не подтверждена → RAW) |
| Нижняя частичная нагрузка | `24* 92` | (trunc0(390625·r − 5·10⁷, 10⁶) + 100)/100 |
| Верхняя частичная нагрузка | `24* 93` | то же |
| Кодировка | `27* 02 24* F0` | c, m → КПП, ступени, катализатор, USA, EFP, DM, упоры, «экран» 103/104/107/108/109 |

`*` — префикс (parity none). 9-значный код HHT (меню 6 «Version coding») **не восстановлен**.

### 8.1 Сброс адаптаций — РЕК, карантин

```
условия: зажигание ВКЛ, 20:B7 = 00; бэкап DTC и адаптаций
CF*(→30) FF(→00)  C1*(→3E) FC(→03)    ← вход: ответы 00 и 03, иначе прервать
E0*(→1F) 00   CF*(→30) 00   C0*(→3F) FC
затем обязателен цикл зажигания; результат ЭБУ не подтверждает
```

### 8.2 Тест клапана продувки Y58/1 — РЕК, карантин

```
условия: 400–1500 об/мин, ОЖ 80–110 °C
вход:    CF* FF  C1* FC (00/03) → 96 (бит 0x40) → D0* 0F → 96 → D4* 00
ON:      96 (бит 0x40) → D4* 1A        OFF: 96 → D4* 00
лимит ON 30 с (таймер прошивки), затем восстановление
restore: 96 → D0* 0B D1* 00 D2* 00 D3* 40 D4* 00 (+ D0* 0F, если зонд отправлялся)
```

## 9. Ошибки и восстановление

| Ситуация | Поведение прошивки |
|---|---|
| Нет AA 55 | до 3 попыток (1 с); затем `Error` |
| Эхо ≠ TX / ACK ≠ ~prefix / тайм-аут | сеанс `Error`, контекст сброшен, без повтора |
| Ошибка при чтении Live Data | повторная инициализация (только чтение, как HFMreader) |
| Ошибка при записи | `FAULT_STOP`: запись блокирована до квитирования, переподключения и повторной идентификации |
| Ошибки паритета/кадра UART | считаются и показываются; байт не отбрасывается |

## 10. Журнал TX/RX

Кольцевой буфер 1536 событий: `seq, t_us, phase (BREAK/SYNC/PREFIX/SELECTOR/ARG), parity,
tx, echo, rx, rxCount, status, risk`. Экспорт JSONL (`/api/trace.jsonl`), схема `hfm.trace.v1`
(REV 1.4 §20). `partial=true`, если получено < 2 байт.

## 11. Открытые вопросы (блокируют VAL)

C-01 назначение банков F1; формат 9-го бита в ответах ЭБУ; реальные тайминги BREAK/пауз;
ширина импульсов blink-кода; VDO-формулы адаптаций; варианты I6A / context H; значения
DTC 118–164; поведение ЭБУ при паузе без обмена (сторожевой таймаут). См. [ROADMAP.md](ROADMAP.md).

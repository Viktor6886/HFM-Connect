# Данные, необходимые для расширения HFM Connect

**Дата:** 2026-11-13 · **Прошивка:** 0.9.1 · **Статус:** перечень входных данных, кода по
нему нет.

## Что это за документ

Здесь перечислено, что нужно получить, чтобы реализовать функции заводского тестера HHT:
- для HFM-SFI;
- для ME-SFI разных поколений;
- для остальных блоков автомобиля: трансмиссии, тормозов, климата, оборудования.

Функции:
- идентификация;
- чтение и стирание неисправностей;
- фактические значения;
- исполнительные механизмы;
- адаптации;
- кодирование;
- ввод в эксплуатацию.

Источники данных:
- декомпиляция программы заводского тестера;
- трассы с автомобиля;
- решения владельца.

Правила D-015 и D-017 действуют:
- дампы, листинги и тексты тестера хранятся вне репозитория;
- в репозиторий попадают только выводы с источником (модуль, `сегмент:смещение`) и уровнем
  подтверждения (ЗАВ / РЕК / ГИП / VAL / БЛОК).

Пока данных нет:
- новые блоки не реализуются;
- функции HFM-SFI, перечисленные ниже, остаются заблокированными.

## 0. Что уже известно о составе заводского тестера

Источник — опись файлов установки (материалы анализа, вне репозитория).

### Состав установки

- **`HHT/PKW` (легковые).** Около 75 модулей блоков. Каждый модуль — пара 16-битных
  библиотек NE: `xxxDEF.DLL` (данные) и `xxxWIN.DLL` (логика).
- **`HHT/NFZ`** (коммерческие, около 200 файлов) и **`HHT/VMOD`** (назначение не
  установлено). Вне области, пока владелец не решит иначе.
- **Общие модули.** Назначение установлено только для HHTWINX и DECOWIN; остальное — по
  именам файлов (ГИП):

| Модуль | Назначение |
|---|---|
| `KS_*.DLL` (`KS_`, `KS_WIN`, `KS_32NT`) | уровень связи |
| `ISODEF`/`ISOWIN` | протокол ISO, какой — не установлено |
| `HHTWINX` | исполнитель шаблонов телеграмм (C-10) |
| `DECOWIN` | функции пересчёта |
| `SGWIN`, `SYSDEF`/`SYSWIN`, `STRWIN`, `UNIWIN`, `GLOBAL`, `GLOPKW`, `PKWDEF`/`PKWWIN` | общие таблицы и выбор автомобиля |
| `KTDEF`/`KTWIN` | не установлено; возможно, быстрый тест всех блоков |
| `GFTEXTnn`, `HLPDEF`/`HLPWIN` | тексты и справка |
| `IDESVCI*`, `CTAPIW*`, `CTPCSC` | интерфейс VCI и смарт-карта |

- **Файлы настроек:** `HHTWIN_PROG.INI`, `HHTWin.INI`, `HHTWIN_Params.ini`, `IdesVCI.ini`.

### Что разобрано

Разобраны только `HFMWIN`/`HFMDEF`, `DECOWIN` — частично. Получено:
- 115 AT-телеграмм;
- таблица режимов времени;
- карты типов V/B;
- статические команды V/B;
- 173 экранных поля;
- опись 52 функций пересчёта (без формул);
- 7 битовых карт DTC;
- 242 текстовых записи.

### Коды модулей в `HHT/PKW`

AAM, AB2, ABS, ADS, AID, AKS, APS, ARA, ASD, BAS, CNS, CRD, CVD, D2B, DBE1, DIE, DM, DM2,
EAG, EDS, EDW, EDW2, EDZ, EFP, EGS, EPH, ERE, ESL, ESV, ESV1, EVE, EZ1, EZS1, FFZ, FGS, GEM,
GM, HAU, HFM, IF1, IF2, KFB, KFZ, KIW, KLA, LH1, LWR, ME1, ME2, MSM1, MSS1, PL2, PML, PMS,
PSE, PSE1, PSZ, SAM1, SEM, SH1, SH2, SKF, TAU, TGH1, TGV1, TSG2, UBF1, UBF2, UVS, VD, VG, ZAE.

По именам (ГИП, требует подтверждения):

| Группа | Коды |
|---|---|
| Двигатель | HFM, ME1, ME2 (ME-SFI), LH1 (LH-SFI), PMS, EZ1 |
| Коробка передач | EGS |
| Тормоза | ABS |
| Климат | KLA |
| Охранная система | EDW/EDW2 |
| Корректор фар | LWR |
| Модуль сигналов | SAM1 |
| Замок зажигания и рулевой колонки | EZS1, ESL |
| Оптическая шина | D2B |
| Диагностический модуль | DM/DM2 |
| Двери | TGV1/TGH1/TSG2 |
| Автономный отопитель | SH1/SH2 |

**Первое, что нужно:** точное соответствие «код модуля → система → автомобили и годы» по
меню заводского тестера.

## 1. Решения владельца (до начала реализации)

1. **Правило «не реализовывать OBD-II, ELM327, CAN, UDS»** (CLAUDE.md). Другим блокам
   нужны другие протоколы.
   - Предложение: отдельные драйверы протоколов рядом с HFM (`HfmSession` не меняется) и
     общий интерфейс сеанса.
   - Правило заменить формулировкой «другие протоколы — только отдельными драйверами, по
     данным из источника».
   - Нужен явный ответ владельца.
2. **Область:** только легковые (PKW) или также NFZ/VMOD.
3. **Автомобили и блоки для испытаний.** Без них функции не получат статус «проверена на
   ЭБУ».
4. **Коммутация линий K** разных блоков (§5).
5. **Границы.**
   - Блоки, которых это касается: иммобилайзер и ключи (DAS, EZS, ESL, EDW), приборная
     панель, SRS.
   - Разрешено: идентификация, чтение неисправностей, стирание обычных неисправностей по
     заводской процедуре.
   - Не реализуется: обучение ключей, отключение иммобилайзера, изменение пробега, сброс
     данных аварии.

## 2. HFM-SFI: чего не хватает для начатых функций

### 2.1 С автомобиля

- **Трассы с 013 545 08 32** — TX/RX (`/api/trace.jsonl`):
  - подключение, идентификация, F1;
  - цикл Live Data на прогретом ХХ и на 2500 об/мин;
  - стирание.

  Это испытания H39–H45, задача #19.
- **Эталонные показания в тот же момент** — фото экрана заводского тестера или другого
  прибора. Нужны для масштабов VDO (#21) и банков F1 (C-01).
- **Трассы с других ЭБУ HFM:**
  - Bosch разных diag index (40–59);
  - M111;
  - VDO другой ревизии (B6).
- **Осциллограмма K-Line при подключении** (логический анализатор): BREAK, AA/55, паритет
  (H2).

### 2.2 Из HFMWIN/HFMDEF

1. **Формулы 52 функций пересчёта** (`1038:0000`…`1038:247e`).
   - По каждой функции нужно:
     - входные смещения ответа;
     - знаковость;
     - константы → формула и единица;
     - какой экран и какой вариант (V/B) её вызывает.
   - Приоритет — адреса VDO: 12:7E, 12:A4/A5, 12:76/77/7A/7B, 22:72/73, 22:74/75, 22:78,
     22:7A/7B, 22:7F, 23:7E/7F/A4, 20:F2, 13:2B.
2. **Двойное чтение (флаг 1)** в шаблонах VDO: 12:7E, 22:7F, 20:F2, 20:45, 20:47, 20:FC.
   Нужен код, обрабатывающий ответ: это 16-битная величина или контрольное повторение?
3. **Самоадаптации VDO 20:45 / 20:47 / 20:43–42** (#20):
   - индексы меню;
   - формулы и нормы;
   - сброс для VDO — тот же шаблон AT87 или другой.
4. **Исполнительные механизмы:** телеграммы AT68–86, AT90, AT97, AT100–114 (D0–D4, DA–DF,
   E0, E4).
   - По каждой нужно:
     - пункт меню и текст экрана;
     - механизм;
     - условия, которые проверяет код тестера (обороты, ОЖ, скорость, время);
     - длительность;
     - телеграмма остановки или восстановления;
     - ожидаемый ответ;
     - варианты и diag index.
   - Отдельно: что за режим включают AT66/67 (`CF FF · C1 FC` / `CF 00 · C0 FC`).
5. **«Variantencodierung»:** чтение и запись 9-значного кода, обучение упоров заслонки/ETA.
   - Нужно:
     - телеграммы;
     - формат данных (цифры → биты);
     - контрольная сумма;
     - проверка после записи;
     - условия.
   - Назначение шаблонов:

| Шаблон | Байты |
|---|---|
| AT64 / AT88 | `10 02 · 22 22 · 10 03 · 22 23 [· 10 04]` |
| AT93 | `E0 FE · E0 FF` |
| AT95 | `13 2B` |
| AT100 | `DE 02` |
| AT109 | `DF 72` |
| AT111 | `DC 80` |
| AT34 | `00 7E · 90 34 · 80` |
| AT94 | 36 нулевых байтов |
| AT8 | шаблон 96 без байтов |

6. **Банки F1:**
   - как экран тестера называет F1 00–0F и 10–1F — «текущие» или «сохранённые» (C-01);
   - F1 30–32 / 40–42 (C-02).
7. **Коды 118–164** (33 предварительных) — полные условия текстов по вариантам.
8. **Идентификация:**
   - таблицы HFMDEF, по которым тестер выбирает вариант (номер ЭБУ, diag index, буква,
     F0:26) → карту DTC, экраны, нормы;
   - зачем тестер читает F0:26/27 и дескрипторы ПЗУ (02/80).
9. **Единицы T1/T2** таблицы режимов времени — код таймера (`KS_*`/`HHTWINX`).
10. **Ввод в эксплуатацию** — есть ли в HFMWIN последовательность экранов: что тестер
    требует и что проверяет.
11. **PMS** (diag 60–79, `PMSDEF`/`PMSWIN`) — если нужен M111 с PMS, то полный паспорт по §4.

## 3. Общий уровень заводского тестера (нужен для всех блоков)

1. **Исполнитель шаблонов** (`HHTWINX`, `KS_*`). Как шаблон `pp 01 ss 00` превращается в
   байты на линии:
   - что значат `01`, `00`, `aa` и однобайтовые `bf 00`;
   - как используется длина ответа ER;
   - где описано пробуждение (BREAK/AA55 у HFM).

   Без этого каждую новую телеграмму придётся подтверждать трассой (C-10).
2. **Протоколы уровня связи** — список и по каждому:
   - скорость, формат кадра (биты, паритет);
   - пробуждение (как у HFM, адрес на 5 бод, быстрое), ключевые байты;
   - тайминги: межбайтовая пауза, ожидание ответа, пауза между запросами, поддержание
     связи;
   - формат сообщения: заголовок, длина, контрольная сумма;
   - эхо, ACK/NACK, коды отказа, повторы.
3. **`ISODEF`/`ISOWIN`:**
   - какой стандарт;
   - список сервисов;
   - коды отрицательных ответов;
   - доступ по ключу (seed/key): для каких блоков и операций.
4. **Выбор автомобиля** (`PKWDEF`/`PKWWIN`, `GLOBAL`, `SGWIN`, `SYSDEF`). Цепочка:
   модель → год и исполнение → список блоков → модуль DLL → контакт диагностического
   разъёма → протокол → адрес блока.
5. **Быстрый тест всех блоков** (если это `KTDEF`/`KTWIN`):
   - порядок опроса;
   - что считается ответом блока;
   - что выводится.
6. **Где выполняется протокол:** в DLL на ПК или во встроенном ПО интерфейса (`IDESVCI*`,
   `KS_32NT`). Если во встроенном ПО, из DLL байты линии не получить — нужны трассы на
   линии.
7. **Тексты:**
   - `GFTEXTnn` и текстовые таблицы модулей: номера языков (00/02/03…) и кодировка;
   - справка HLP.
8. **Файлы INI** — параметры интерфейса и таймингов.

## 4. Паспорт блока: что нужно по каждому модулю (`xxxDEF` + `xxxWIN`)

По каждому блоку нужен тот же набор, что уже извлечён для HFM.

1. **Назначение:** система, автомобили, годы, двигатели, номера блоков, поставщик.
2. **Подключение:**
   - контакт разъёма: X11/4 38 конт., OBD 16 конт. или другой;
   - протокол из §3, адрес, скорость, пробуждение.
3. **Идентификация:**
   - запрос и разбор ответа: номер, HW/SW, вариант, diag version;
   - таблица «вариант → какие таблицы применять».
4. **Реестр телеграмм.** Все шаблоны с полями:
   - номер, байты;
   - длина ответа, тайминг;
   - признак «чтение» или «изменение состояния».
5. **Память неисправностей:**
   - чтение и формат: биты или коды, статус (текущая/сохранённая), счётчики, условия
     возникновения;
   - карты кодов по вариантам, тексты;
   - стирание: последовательность, условия, проверка результата.
6. **Фактические значения:**
   - экраны, телеграммы, позиции байтов;
   - формулы (функции пересчёта), единицы;
   - нормы и условия, при которых они действуют.
7. **Исполнительные механизмы:**
   - старт и стоп, длительность;
   - условия и блокировки;
   - восстановление, ожидаемый ответ;
   - предупреждения тестера.
8. **Адаптации и обучение:** чтение, сброс, обучение — последовательность, условия,
   проверка.
9. **Кодирование:**
   - чтение и запись;
   - формат (поле → опция), допустимые значения;
   - контрольная сумма, доступ по ключу;
   - проверка после записи.
10. **Процедуры** (ввод в эксплуатацию, обучение после замены, прокачка тормозов и т. п.).
    Нужно пошаговое описание логики WIN-модуля: экраны, условия перехода, телеграммы,
    проверки, обработка ошибок. Только таблиц недостаточно: устройство будет выполнять
    процедуры как данные (сценарии), а не как машинный код тестера.

### Формат передачи

- JSON или CSV по каждому модулю.
- Адреса `сегмент:смещение`.
- Фрагменты листинга Ghidra по спорным местам.

Скрипты, которыми разбирались HFMWIN/HFMDEF (`decode_sg_table`, `istwert_records`,
`extract_dtc_tables`, `extract_fault_texts`, `conv_inventory`), стоит прогнать на остальных
модулях. Если формат DEF общий, большая часть таблиц извлечётся автоматически.

**Предлагаемый порядок модулей:** ME1, ME2 (двигатель) → EGS (АКПП) → ABS (тормоза) → KLA
(климат) → остальные по потребности.

## 5. Оборудование

1. **Распиновка.** Какой контакт X11/4 (38) или OBD (16) у каждого блока на конкретных
   моделях и годах. Таблица разъёмов в исходных документах есть
   (`DTC_Connector_Pinouts_38-16-8.pdf`), но для ваших автомобилей её нужно подтвердить
   по WIS.
2. **Коммутация линий.** У адаптера FTDI одна линия K. Варианты:
   - отдельный кабель или переходник на каждый блок;
   - плата коммутации (реле или аналоговые ключи) под управлением ESP32.

   Нужны выбор владельца и схема.
3. **Требования протоколов к физическому уровню:**
   - нестандартные скорости;
   - адрес на 5 бод (на FT232R — bit-bang или управление BREAK);
   - линия L;
   - CAN, если встретится: контроллер TWAI в ESP32-S3, внешний трансивер, отдельный
     разъём.
4. **Плата:** объём flash/PSRAM (N8R2 или N16R8). От него зависит, поместятся ли данные
   десятков блоков; иначе нужна карта microSD.
5. **Напряжение бортсети** — делитель на АЦП, для условий сервисных операций.

## 6. Трассы с автомобиля (по каждому блоку)

- **Идентификация блока:** номер, HW/SW, diag version; автомобиль — модель, год, двигатель,
  коробка передач.
- **Журнал TX/RX устройства:**
  - подключение и идентификация;
  - чтение неисправностей;
  - фактические значения в двух режимах.
- **Эталон** — показания заводского тестера в тот же момент (фото экрана).
- **Операции записи** — трасса заводского тестера (логический анализатор на K-Line),
  выполняющего эту операцию на автомобиле. Без такой трассы или однозначного кода тестера
  последовательности, изменяющие состояние блока, на автомобиль не отправляются.

## 7. Порядок работ (предложение)

1. Закрыть HFM-SFI: трассы (§2.1) и пункты 1–5 из §2.2.
2. Уровень связи: §3, пункты 1, 2 и 6.
3. Выбор автомобиля (§3, п. 4) и распиновка (§5, п. 1) — получится карта блоков.
4. Решения §1, пункты 1 и 4: архитектура драйверов и коммутация линий.
5. Блоки по одному: паспорт (§4) → только чтение → трасса → операции записи.

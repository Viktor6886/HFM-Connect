# Протокол диагностики Bosch HFM-SFI (Mercedes-Benz M104/M111) по K-line

Спецификация восстановлена статическим анализом HFMreader 1.1.1-public.1. Это не официальная документация Bosch или Mercedes-Benz. Все ссылки ведут на байт-код модулей из `HFMreader.exe` (SHA-256 `b5aa7e0ea27761802f2fcec41a197923502faf2dbc6722e3ede694ac0b31a2ed`).

Нотация ссылок: `модуль › объект кода Lстрока @bc+смещение`. Строка — номер строки исходного кода из таблицы строк байт-кода, смещение — позиция инструкции CPython 3.12 внутри объекта кода. SHA-256 кода модулей и смещения их zlib-блоков в EXE собраны в `../evidence/evidence_index.md` и `../evidence/pyz_modules.csv`.

Статусы утверждений:

| Код | Значение |
|---|---|
| **CS** | Прочитано напрямую из констант и логики байт-кода |
| **CD** | Прочитано напрямую из поставляемого JSON |
| **AV** | Автор программы пометил VERIFIED по полевым данным ЭБУ 013 545 13 32. Мы на автомобиле не перепроверяли |
| **AH** | По оценке автора «высоко вероятно» |
| **AC** | Кандидат или условная интерпретация, автор пометил как непроверенную |
| **IN** | Наш вывод (интерпретация аналитика) |

## 1. Физический уровень

| Параметр | Значение | Статус | Ссылка |
|---|---|---|---|
| Линия | K-line, полудуплекс, адаптер KKL (FTDI, «409.1») | CS/док. | HARDWARE_CONNECTION.md |
| Разъём W124 X11/4 (16 конт.) | гнездо 8 = K-line, гнездо 1 = масса, гнездо 16 = +12 В. Со стороны OBD-кабеля: 7 = K, 4/5 = GND, 16 = +12 В | док. | HARDWARE_CONNECTION.md (sha256 `bff01df2…`) |
| Скорость | 9600 бод | CS | winserial › configure_dcb L46 @bc+98 |
| Формат | 8 бит данных, 1 стоп-бит | CS | configure_dcb L48 @bc+146, L50 @bc+188 |
| Режимы паритета | `none` = NOPARITY (8N1, кадр 10 бит). `space` = SPACEPARITY (8S1, кадр 11 бит, бит паритета 0) | CS | configure_dcb L47–49 @bc+112..176 |
| Переключение паритета | GetCommState/SetCommState **перед каждым байтом** | CS | serial_transport › exchange L58; winserial › set_parity L118-123 |
| Таймауты Win32 | ReadInterval 50 мс, ReadTotalConst 100 мс, WriteTotalConst 100 мс | CS | winserial › _set_timeouts L115 |
| Ожидание ответа | 2 байта (эхо + ответ) в течение 0,75 с, иначе TimeoutError | CS | winserial body L64 @bc+12; read_exact L139-152 |
| Очистка | PurgeComm(0x0F) | CS | winserial › purge L126 |
| Эхо | Каждый переданный байт читается обратно и должен совпасть с TX, иначе «echo mismatch» и прерывание | CS | protocol › _exchange L81-82 |

**Смысл двух режимов паритета (IN).** Вероятно, ЭБУ работает в 9-битном режиме UART: 8 бит данных плюс бит-маркер, как в режиме 2/3 у 8051.
- В режиме 8N1 после бита D7 сразу идёт стоп-бит (=1). Его ЭБУ воспринимает как 9-й бит = 1, так помечаются **префиксные (командные) байты**.
- В режиме 8S1 9-й бит = 0, так помечаются **селекторы, индексы и аргументы**.

Такое понимание подтверждает `candidates.json`: в нём `parity:1` → режим `none` и разрешено только для `20`/`21`, а `parity:0` → `space` (recipe_executor › _hht_transaction L115; _validate_plans L97-99).

Паритет **принимаемых** байтов программа не проверяет: журнал пишет `rx_parity: None`, а в коде есть строка «parity_marker_provenance: unavailable on native KKL; unused by all 29 callbacks» (recipe_executor L120). Проверка паритета в DCB включена, но `fAbortOnError` не установлен, поэтому ошибки паритета при приёме фактически игнорируются (IN).

## 2. Инициализация (BREAK + синхронизация)

Источник: `serial_transport › HFMSerialTransport.initialize L35-51`. Константы: BREAK_SECONDS = 0.177 (@bc+10), POST_BREAK_SECONDS = 0.214 (@bc+14). Статус CS.

```
set_parity(none); purge
BREAK ON (K-line = 0) ............ 177 мс
BREAK OFF
пауза ............................ 214 мс
purge
set_parity(space)
TX  AA
RX  AA 55          (AA = эхо адаптера, 55 = ответ ЭБУ)
иначе: TransportError "expected AA 55 synchronization"
```

Повторы:
- **Живые данные.** До 3 попыток инициализации с паузой 1,0 с (reader_service › class body L176-177; _initialize L435-446).
- **Сеансы управления.** Каждая операция идёт в отдельной «проводной» сессии: закрыть и снова открыть порт, затем инициализация. Между сессиями выдерживается тишина не менее 1,0 с. После TransportError или TimeoutError допускается один повтор через 2,0 с, и только пока нет неразрешённой операции управления (hht_control.session › body L29-32; _start_session L106-136).

## 3. Модель транзакций

| Тип байта | Паритет | Ответ ЭБУ | Проверка | Ссылка |
|---|---|---|---|---|
| **Префикс** (opcode/страница) | none | побитовое дополнение `tx ^ 0xFF` | несовпадение ведёт к ProtocolError | protocol › read_parameter L63-67; field_protocol › read_group L48-52 |
| **Селектор/индекс** (после префикса чтения) | space | 1 байт данных | — | field_protocol L55-59 |
| **Аргумент записи** (после префикса управления или стирания) | space | ожидается дополнение аргумента: `00→FF`, `FF→00`, `FC→03` | несовпадение ведёт к ProtocolError | dtc_protocol › _transaction L146-148 (CS); обобщение до «дополнения» — IN |
| Эхо | — | равно TX | несовпадение ведёт к ProtocolError | все _exchange |

**Контекст страницы.** ЭБУ помнит последний префикс. Рецепты из одних селекторов (`B9 B7`, `96`, большинство HHT-битов) опираются на ранее отправленный префикс. Для таких рецептов программа требует явный «prelude» — предшествующее чтение группы из whitelist (recipe_executor › _validate_plans L94-95; field_kit L23-30). Сама программа называет эквивалентность контекста «UNVALIDATED test assumption» (AC).

Обмен идёт строго запрос–ответ: следующий байт отправляется только после приёма эха и ответа на предыдущий. Явных межбайтовых задержек в коде нет. Время реакции ЭБУ в коде не задано, ограничено только таймаутом 0,75 с.

## 4. Идентификация ЭБУ

Источник: `ecu_identification_protocol › read L23-33`, `ecu_identification › parse L56-70`. Статус CS.

```
для i = 00..1B:  TX F0 (none) → 0F ;  TX i (space) → byte[i]
```

| Байты | Содержимое |
|---|---|
| 0–1 | код производителя: `2C 42` = BOSCH |
| 2–11 | ASCII-идентификатор, 10 символов, отображается как `XX XXXXX XXX` |
| 12–21 | ASCII-номер ЭБУ, 10 цифр, отображается как `013 545 13 32` |
| 22–23 | дата HW: неделя/год, BCD |
| 24–25 | дата SW: неделя/год, BCD (недопустимая неделя → None) |
| 26–27 | индекс диагностики `%02X/%02X`, например `41/00` |

Пример ответа встроенного симулятора — синтетические данные, не захват с автомобиля:
`2C 42 4D 32 32 38 33 32 30 56 52 30 30 31 33 35 34 35 31 33 33 32 35 92 46 92 41 00`
→ BOSCH, «M2 28320 VR0», 013 545 13 32, HW 35/92, SW 46/92, diag 41/00.

Функции записи (стирание, сброс, управление) программа разрешает только при всех условиях:
- производитель BOSCH;
- номер `0135451332`;
- индекс `41/00`;
- `raw[2], raw[4], raw[5] == 'M', '2', '8'`.

Источник: `is_validated_clear_target` L74-77; `ControlSession._target` L95-98.

## 5. Память неисправностей (DTC)

### 5.1 Чтение (CS)

```
для index = 00..1F:  TX F1 (none) → 0E ;  TX index (space) → битовая карта (1 байт)
```

- Индексы `00..0F` — банк **stored** (сохранённые).
- Индексы `10..1F` — банк **current** (текущие), нормализованный индекс = index − 16.
- `scan_stored()` читает только `00..0F`.

Источник: `dtc_protocol › DtcReadOnlyProtocol L41-43, scan_indexes L63-79`; `dtc › _status_and_normalized_index L131-136`.

### 5.2 Декодирование битов (CS)

```
для каждого бита b (0 = LSB … 7):
  bit_position = norm_index*8 + b + 1
  dtc = HFM_BASE_DTC_NUMBERS[bit_position-1]   (152 элемента, dtc › <module> L14)
  dtc = apply_variant_remaps(dtc, variant)
```

- Вариант по умолчанию: manufacturer = 1, group = 'h', diagnosis_index = 41. Перенумерация (remap) к нему не применяется.
- Таблицы remap для групп 'o', индекса 49 и индексов 50–55: `../dtc/variant_remaps.json`.
- Банк из 16 байт покрывает только позиции 1–128. Позиции 129–152 (24 кода) при 16 байтах на банк недостижимы.
- Полная карта: `../dtc/bit_map.csv`. Каталог из 163 записей с переводом: `../dtc/dtc.csv`.

Проверка на сценариях симулятора:

| Сценарий | Байт | Позиция | Результат |
|---|---|---|---|
| maf-stored | index 00 = 0x40 | 7 | DTC 10 «MAF: обрыв» |
| maf-current | index 10 = 0x40 | 7 | DTC 10 «MAF: обрыв» |
| oxygen-stored | index 02 = 0x08 | 20 | DTC 24 «верхний лямбда-зонд: холодный / обрыв» |

### 5.3 Стирание (CS, изменяет состояние ЭБУ)

Источник: `dtc_protocol › DtcClearProtocol L91-94, clear_and_verify L116-132`.

```
предусловие: полный скан stored 00..0F; если все байты 00 — стирание не выполняется
пауза 200 мс
10(none)→EF ; 00(space)→FF ; пауза 200 мс
F3(none)→0C ; FF(space)→00 ; пауза  50 мс
10→EF ; 00→FF ; пауза 500 мс
10→EF ; 00→FF ; пауза 200 мс
F3→0C ; FF→00 ; пауза  50 мс
10→EF ; 00→FF ; пауза 500 мс
10→EF ; 00→FF
проверка: полный скан 00..1F; «verified» только если все 32 байта = 00
```

Программа разрешает стирание только для ЭБУ 0135451332 и после ввода фразы «CLEAR DTC 0135451332».

## 8. Чтение конфигурации и адаптаций

Источник: `hht_control › recipes L11-47, configuration L14-32`. Статус AC: автор указывает «conditional HHT variant1 legacy; NOT vehicle validated». В ответы входят ACK префиксов.

| Функция | Рецепт (* = префикс) | Ответы | Формула |
|---|---|---|---|
| Конфигурация | 27* 02 24* F0 | [D8, c, DB, m] | биты, см. ниже |
| Время впрыска | 20* 54 20* 55 B7 | [DF, lo, DF, hi, rpm] | ((lo + 256·hi)//50)/10 мс; при rpm = 0 нет данных |
| Лямбда-регулирование | B9 B7 | [λ, rpm] | 390625·λ//10⁶ − 50 % |
| Адаптация ХХ | 24* 90 | [DB, r] | trunc0(275·r − 35000, 1000)/10 кг/ч |
| Адаптация нижней частичной нагрузки | 24* 92 | [DB, r] | (trunc0(390625·r − 5·10⁷, 10⁶) + 100)/100 (множитель) |
| Адаптация верхней частичной нагрузки | 24* 93 | [DB, r] | то же |

Биты конфигурации (c — байт кодировки, m — маска «не применимо»):
- КПП: при m&1 — нет данных; иначе c&1 → АКПП, иначе МКПП.
- Число ступеней АКПП: при m&0x21 или отсутствии c&1 — нет данных; иначе c&0x10 → 5, иначе 4.
- Катализатор: при m&2 — нет данных; иначе c&2 → «NO CAT», иначе «CAT».
- USA: признак есть, если не установлен m&4 и установлен c&8.
- EFP/TPM: при m&8 — нет данных; иначе c&0x20.
- Диагностический модуль: при m&8 — нет данных; иначе c&0x80.
- Упоры дросселя: m&0x10 → «Not taught», иначе «Taught».
- «Экран» (кандидат): при m&3 — нет; иначе
  - если c&2: c&1 → 107, иначе 108;
  - если не c&2: c&1 → (c&4 → 109, иначе 103), иначе 104.
- Экраны 107/108 показывают напряжение CO-потенциометра, остальные — лямбда-регулирование.

### 8.1 Сброс адаптаций (CS, изменяет состояние ЭБУ)

```
условия: зажигание ВКЛ, двигатель стоит (20:B7 == 00); идентификация 0135451332 / 41/00;
         перед сбросом — скан DTC и снимок данных; подтверждение действует 20 с
CF*(→30) FF(→00)  C1*(→3E) FC(→03)       ← проверка входа: ответы 00 и 03, иначе прервать
E0*(→1F) 00       CF*(→30) 00            C0*(→3F) FC
затем обязателен цикл зажигания (выкл/вкл). Факт стирания и переобучения программа не проверяет.
```

Источник: recipes L24; session › _recipe L164-168, _entry_status L304-306, _conditions L260-261, confirm L319-322.

### 8.2 Тест клапана продувки адсорбера (CS, исполнительный механизм)

```
условия: 400–1500 об/мин, температура ОЖ (HHT) 80–110 °C
вход:    CF* FF C1* FC (проверка 00/03) → 96 (бит 0x40 ответа обязателен) → D0* 0F (sonde) → 96 → D4* 00 (OFF)
ON:      96 (бит 0x40) → D4* 1A ;  OFF: 96 → D4* 00
локальный лимит ON 30 с, затем restore
restore: 96 → D0* 0B D1* 00 D2* 00 D3* 40 D4* 00 (+ D0* 0F, если sonde отправлялся)
```

Источник: session › confirm L324-331, purge L333-340, restore L342-350, tick L352-355, _ready L294-301.

## 10. Рекомендации для ESP32-S3

Это проектные рекомендации аналитика (IN). В HFMreader их нет, их нужно проверить логическим анализатором.

1. **Трансивер.** K-line 12 В через L9637D, MC33290, SN65HVDA195 или транзисторную схему; RX видит эхо собственного TX. Питание +12 В берётся с гнезда 16, масса — с гнезда 1.
2. **SPACE-паритета в UART ESP32 нет.** Есть только DISABLE, EVEN и ODD.
   - Для байта со «space» выбирайте режим так, чтобы бит паритета был 0: при чётном числе единиц — EVEN, при нечётном — ODD (`hfm_space_needs_odd()` в `decoders/c/hfm_decode.h`).
   - Для префикса используйте UART_PARITY_DISABLE (8N1), как HFMreader.
   - Менять режим только после `uart_wait_tx_done()` и приёма эха.
3. **BREAK 177 мс.** `uart_write_bytes_with_break()` ограничен 255 битовыми интервалами (≈ 26,6 мс при 9600), этого мало. Отключите TX от UART через GPIO-матрицу, удерживайте 0 в течение 177 мс, затем верните TX к UART (или используйте `uart_set_line_inverse` на время паузы). После BREAK выдержите 214 мс и очистите RX FIFO.
4. **Приём.** Читайте строго 2 байта на каждый TX (эхо + ответ) с таймаутом 750 мс. Флаги ошибок паритета и кадра на приёме не являются основанием отбросить байт: программа их не проверяет. Включите событие ошибок и журналируйте их, чтобы выяснить реальный формат кадров ЭБУ.
5. **Межбайтовые паузы** программа не задаёт: следующий байт отправляется сразу после ответа. Поведение ЭБУ при длительной паузе (сторожевой таймаут сессии) не установлено. Опрашивайте непрерывно, а при таймауте заново выполняйте BREAK и синхронизацию.
6. **Порядок опроса** — профиль full8 (28 транзакций). MAF (48 и 49) читайте в одном цикле.
7. **Функции записи** (стирание, сброс, продувка) повторите вместе с охранными условиями (§5.3, §8.1, §8.2). Не повторяйте их автоматически после ошибки.

## 11. Открытые вопросы

- Формат 9-го бита в ответах ЭБУ: на KKL его невозможно наблюдать (CD: «unavailable on native KKL»).
- Масштабы MAF, температуры воздуха и O2 автор подтвердил не независимой метрологией, а частично (AH/AV).
- 29 HHT-рецептов являются условными (AC). Перечень Bosch-вариантов (I6A и «context H») не идентифицирован.
- Значение кодов DTC 118–164 частично не подтверждено (статус «unverified» в каталоге).
- Байты D7 и 98 и их связь с режимами ЭБУ являются кандидатами.
